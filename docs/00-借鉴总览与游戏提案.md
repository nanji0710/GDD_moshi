## 1. 底座到底是个什么东西

### 1.1 事实清单

| 维度 | 事实 |
| --- | --- |
| 形态 | 网页游戏，双击 `index.html` 就能跑；`<script>` 顺序加载 40+ 个文件，全局命名空间 `window.CM` |
| 规模 | `js/` 下 **107 个 JS、约 39 MB**（其中 59 个 `geo_*.js` 占 36 MB 是地图数据） |
| 依赖 | **零 npm 依赖**。构建/测试脚本是 node ESM，无 `node_modules` |
| 渲染 | 单张 `<canvas id="map">` + DOM 覆盖层做 UI |
| 主循环 | `js/main.js:238-261`，`requestAnimationFrame` + 裸 `dt`（**没有固定步长**） |
| 核心文件 | `render.js` 3190 行、`ui.js`、`pages.js` 1354 行、`style.css` 2109 行、`sim.js` 1451 行、`metro.js` 925 行、`agents.js` 754 行、`util.js` 314 行、`config.js` 218 行 |
| 内容量 | 54 城 × 真实线网前 4 站 = 54 条线 215 站；397 条线 7836 站的"真实规模"只做展示 |

### 1.2 一句话架构

> **一个 120×96 格（30 km × 24 km）的世界坐标，一套"弧长参数化"的轨道，一堆"按视觉需要现场摆"的实体，加上一层手写 DOM UI。**

它和你的游戏最像的地方是：**你也要画一条铁路，上面跑一列车，列车由多节车厢组成，车厢在弯道上要正确转向**。这部分底座做到了出版级。

它和你的游戏最不像的地方是：**底座里的一切动态实体都是"画给你看的"，不是"真的存在"**。

```js
// city-and-metro/js/agents.js:469
if (!show) { for (const c of this.cars) c.dying = true; return; }
```
> 汽车开出视野 → 直接标记死亡清掉；回来看，那辆车是另一辆。
> 客流不是人，是 `legLoad()` 返回的一个数字（`agents.js:239`）。
> 碰撞不是碰撞，是 `list[i].s = list[i-1].s - gap` 这样一句"位置赋值"（`agents.js:460`）。

这是底座刻意做的取舍（经营游戏只要"看得见"）。**你的游戏一个都不能这么干**——丧尸必须死了才算死，子弹必须真的撞到才掉血。这一点决定了：**渲染/轨道/UI 可以抄，战斗/实体层必须重写。**

## 4. 游戏设计提案：《末世列车》

> 这一节是我按底座能提供的能力反向设计的玩法。原型已经实现了 §4.2–§4.5 的核心。

### 4.1 一句话

> 你驾驶一列**改装过的货运列车**，把还活着的人送到 11.6 km 外的避难所。车厢顶上装的是你唯一的火力，而铁轨上从来不缺愿意爬上车的东西。

### 4.2 核心循环

```
        ┌──────────────────────────────────────────────────┐
        │                                                  │
   [站台] 补给/维修/装武器 ──→ [区间] 列车高速推进 ──→ [尸群] 拦路/扒车
        ↑                            ↓                       │
        │                     撞飞、碾压、清障                │
        └──────── 到达下一站（幸存者上车 / 新武器解锁）────────┘
```

三个设计支点：

1. **速度即生命**。前方轨道上的丧尸会"拖慢"列车（人体路障），所以清障不是可选项——**机枪不是为了杀而杀，是为了让车跑起来**。这一条把"打丧尸"和"开列车"焊死在一起。
2. **停站是最危险的时刻**。列车停着 = 丧尸围上来 = 车体掉耐久。你必须决定：多花 8 秒补弹药，还是马上跑。
3. **每节车厢是一个独立的血条**。车厢打爆 = 上面的武器全废 + 总耐久掉一格。所以"把最强的炮装在中间车厢"是个真实的取舍。

### 4.3 车厢武器挂点（核心机制）

**数据结构**（这就是第一个要写对的函数，`sim-analyst` 在报告里叫它 `carMount`）：

```js
// 车厢布局：车厢中心里程 = 列车中点里程 + (k - (n-1)/2) * (车长 + 车距)
// 关键：车长 22 m / 间隙 2.2 m 是"逻辑节距"，间隙只在渲染时缩进，不参与定位
carPose(k, sTrain) -> {
  cs: 中心里程,                 // 沿轨道弧长
  x, y, h: 世界坐标 + 轨面高程,  // posAt(path, cs)
  a: 切线角,                     // 车头方向
  ox, oy: 单位切向量,            // (cos a, sin a)
  nx, ny: 单位法向量             // (-sin a, cos a)
}

// 车顶挂点：沿车身前后各偏 26%，高度 = 轨面 + 车高 + 0.7
slotPos(car, j) -> {
  x: car.x + car.ox * (j ? +6 : -6),
  y: car.y + car.oy * (j ? +6 : -6),
  h: car.h + CAR_HEIGHT + 0.7,
  a: car.a
}
```

**挂点规则**：每节车厢 **2 个**挂点（前 / 后），4 节车厢 = **8 个挂点**。挂点限制武器类型（重武器只能装中间车厢，近防只能装两端），这是"装在哪"的第一层决策。

**定位必须全在世界空间算**：炮塔位置、目标位置、弹道，全用 `(x, y, h)`，最后一步才过一次 `P()` 投到屏幕。这样透视缩短、2.5D 倾斜、缩放全部自动正确。**反例是底座的乘客/车门**（`agents.js:339-358`），它们在屏幕空间做偏移，缩小后不变形但也不跟世界绑定，只能做纯装饰。

### 4.4 武器表（第一版 5 种）

| 武器 | 射程 | DPS | 模式 | 特点 | 定位 |
| --- | --- | --- | --- | --- | --- |
| **12.7 mm 机枪塔** | 95 m | 46 | 直射 | 便宜、万金油、曳光好看 | 起手武器 |
| **凝固汽油喷射器** | 42 m | 150 | 锥形（6 目标） | 近身清场王，耗弹药快 | 防爬车 |
| **35 mm 近防火炮** | 175 m | 60 | 三点射 | 打得准、射程最远、节奏慢 | 提前削排 |
| **电磁弧塔** | 70 m | 62 | 连锁 3 目标 | 一发串三只，耗弹快 | 中段挂点 |
| **82 mm 迫击炮** | 230 m | 38（×4 溅射） | 曲射 | 超远 + 大范围，射速极慢 | 清尸群 |

**升级**：每把武器 Lv1–3，升级提升伤害 1.45×/2.1×、射速 1.15×/1.3×、射程 1.08×/1.16×，成本 1.8×/3.0×。拆除回收 40%。

**决策深度在哪**：
- **射程 × 车厢位置**：前排挂短射程高 DPS（喷火），后排挂长射程（迫击）。车头朝哪边，火力覆盖就不一样。
- **弹药经济**：8 个挂点全装最贵的武器，弹药会在 3 分钟内打空，然后你就是一列罐头。
- **升级 vs 铺开**：3 级机枪（DPS 96）比 3 把 1 级机枪（DPS 138）贵，但只吃一份弹药——**弹药效率是隐性维度**。

### 4.5 丧尸与波次

**四种行为层**（从便宜到贵）：

| 层 | 行为 | 作用 |
| --- | --- | --- |
| L1 游荡 | 从废墟/两侧往轨道聚，目标 = 最近的车厢 | 数量压力 |
| L2 拦路 | 站在轨道上，**直接给列车减速**（前方 N 只 → 速度 ×(1−0.055N)） | 逼你清障 |
| L3 扒车 | 贴身啃咬，掉单节车厢耐久（7 伤 / 1.1 秒） | 真实损失 |
| L4 精英 | 3.4× 血、2.2× 伤、更慢，血条可见 | 节奏点 |

**列车本身也是武器**：车头 7 m 内的丧尸被直接碾死（260 伤），同时掉一点速度 + 屏幕抖动。这是"爽感"的免费来源，也让"一路开过去"有了画面。

**波次导演**（不模拟历史，直接补齐）：

```js
// 想清楚"此刻场上该有多少只"，然后补齐差额 —— 底座 fillGroup 的做法（agents.js:137-148）
quota  = min(MAX_ALIVE, 88 * intensity)
intensity = 1 + 里程km * 0.55 + 波次 * 0.22
每 26 秒：从前方 150–300 m 涌出一大群（10 + intensity * 5 只）
```
> 这条建议来自 `sim-analyst`：**不模拟前 20 波怎么积累的，直接按公式算此刻该有多少只**，能砍掉一半状态机代码。

| 站点 | 里程 | 类型 | 事件 |
| --- | --- | --- | --- |

| 钢桥北岸 | 1.9 km | 铁桥 | 桥面窄，丧尸只能从两端上来 |

### 4.7 难度与长线

- **四档难度**照抄底座的决策表：只拧"不可控"的旋钮（丧尸血量、生成频率、补给价格），**不拧**"可控"的（玩家 DPS、弹药效率）——算得对就该赢。
- **战役**：6 站一局 = 1 个"章节"，通关解锁下一段路线（更长、更强、新武器）。
- **长线**：路线图（atlas 改造）→ 章节选择 → 每周挑战（固定种子 + 排行榜）。

### 4.8 手感要点（最容易做砸的地方）

| 要点 | 具体做法 |
| --- | --- |
| 命中反馈 | 命中闪白 + 血花 + 飘字；**击杀必飘 "+3 废料"** |
| 屏幕震动 | 在投影原点 `ox/oy` 上加抖动，**所有绘制统一抖**，成本为零（这个技巧是 `render-analyst` 给的） |
| 目标选择 | 射程内**最近**优先，但加"威胁加权"（正在啃车的 +30% 权重），否则玩家会觉得炮塔眼瞎 |
| 炮塔转向 | 转速限制（2–5 rad/s），转不到不许开火——这条制造了"布局"的价值 |
| 卡车反馈 | 车厢受击闪红 + 耐久条 + 震动，HUD 立刻变红 |
| 减速解释 | 前方丧尸数直接上 HUD，否则玩家不知道为什么突然变慢 |

### 4.9 不要做的事（第一版砍掉）

1. ❌ 拖放改装（底座全仓库 `draggable` 零命中是有原因的，点击流成本 1/5）
2. ❌ 多人/联网（会逼你从第一行代码做确定性模拟）
3. ❌ 手工驾驶列车（你是"指挥官"不是"司机"，否则没法布火力和看战场）
4. ❌ 真实寻路 / 导航网格（丧尸走直线 + 绕障碍就够了）
5. ❌ 车厢内部视角（第一版不做，做 2.5D 俯视）
6. ❌ 30 种武器（5 种 × 3 级的组合已经 8 个挂点装不完）
7. ❌ 存档云同步（本地 + 导出 JSON 足够）
8. ❌ 战役三层结构（底座"公司层 + 战役层 + 城市层"的经验教训就是：**别叠**）

### 5.2 两条铁律

1. **单位统一成米**。底座用 250 m/格，导致"车厢长 0.08 个单位、武器射程 0.4 个单位"，全靠比值才没出错（`sim-analyst` 特别警告过）。新游戏第一件事就是定 `1 单位 = 1 米`。
2. **只有一条时间轴 + 固定步长**。
```js
acc += dt * speed;
while (acc >= 1/60) { step(1/60); acc -= 1/60; }   // 逻辑
render(dt, acc / (1/60));                           // 渲染插值
```
底座的"游戏时钟 vs 视觉时间"双轨制在动作游戏里是灾难：**玩家瞄准的和列车实际所在的不是同一时刻**。

### 5.3 数据驱动（这条决定你能不能商业化）

```json
// data/weapons.json —— 数值改动不碰代码
{ "mg": { "range": 95, "dps": 46, "rof": 9, "ammoPerShot": 1, "mode": "hitscan", "cost": 90 } }

// data/level_01.json —— 关卡是数据，不是代码
{ "length": 11600, "control": [[0,0],[700,-40]], "stations": [{"km":0,"name":"旧城货运站"}] }
```
理由很实际：**要商业化就必须把"表达"重写，"数据"是你的**。数值表、关卡表、武器表从第一天就独立出来，重写代码时它们不用动。

### 5.4 渲染层级（照抄底座的分层顺序，`render.js:1747-1943` 那张表）

```
1. 天空 / 远景渐变
2. 地表色块 + 斑块（chunk 缓存）
3. 道路 / 河道（世界空间多边形）
4. 地表贴花：血迹、弹孔、辙印（**烘焙进 chunk 缓存，不要逐帧画**）
5. 静态道具：废墟 / 树 / 报废车（按高度排序：底 → 侧墙 → 屋顶）
6. 轨道：道砟 → 枕木 → 钢轨 → 桥墩
7. 动态对象：**丧尸与车厢按投影 y 排序后逐个画**（这样能正确前后遮挡）
8. 特效：弹道 / 爆炸 / 飘字
9. DOM HUD
```
> 第 4 层是最容易被忽略的免费午餐：**把血渍烘焙进地面 chunk 缓存**，战场"越打越脏"且零额外开销。这个技巧是 `render-analyst` 从底座的 chunk 架构里挖出来的。

### 5.5 特效容器要重写（底座 fx 的 4 个硬伤）

| 硬伤 | 后果 | 改法 |
| --- | --- | --- |
| 上限 160 且用 `shift()` 淘汰 | 一次齐射 200 发就把所有特效挤掉 | 分类对象池 |
| `t` 在 `drawFx` 里推进 | 暂停时会错乱 | 更新与绘制分离 |
| 从不设 `globalCompositeOperation='lighter'` | 爆炸没有"光" | 加发光层 |
| 全部画在最上层 | 血渍压不住车 | 分前后两层 |

### 5.6 存档 schema 建议

```json
{
  "fmt": "zp-train-save", "ver": 1, "at": 1731XXXX,
  "fp": "level_01@1",          // 关卡指纹：内容变了直接拒绝载入
  "run": { "s": 1240, "v": 26, "fuel": 74, "ammo": 900, "scrap": 210, "wave": 6 },
  "cars": [{ "hp": 640, "slots": [{ "k": "mg", "lv": 2, "aim": 0.3 }, null] }],
  "stats": { "kills": 312, "shots": 1904 }
}
```
规则（来自 `sys-analyst` 的 12 条坑清单）：**有字段就必须有消费点**（底座有 3 个死字段/死 API）；不要存 Map/Set/函数；不要存浮点的"当前动画时刻"（用纯函数从 `(leg,t)` 反解）。

## 6. 工程方式：这才是最该照抄的东西之一

底座是**一个人能维护 107 个文件 / 39 MB 数据**的原因不是代码好，是工程纪律好。

| 做法 | 具体 | 为什么值得抄 |
| --- | --- | --- |
| **零依赖** | 没有 `node_modules`，没有打包器 | 5 年后还能跑；新游戏直接双击 `index.html` |
| **核心零 DOM** | `sim.js` / `metro.js` 不碰 document，`simcheck.mjs` 用 node `vm` 直接跑 91 条断言 | 不用浏览器就能测引擎，**这是能天天跑回归的前提** |
| **批量冒烟** | `smoke-cities.mjs` 无头浏览器逐个开局 54 城 | 关卡制游戏同样适用：批量跑 20 关 |
| **账目恒等式** | `audit.mjs` 验证"收入−支出=结余"之类的 A–G 恒等式 | 战斗游戏可以验"子弹数 = 命中 + 未命中 + 飞行中" |
| **截图审计** | `shoot.mjs` 场景化截图 + 收集 console 报错 | **视觉回归**，改配色/布局不靠肉眼 |
| **CDP 零依赖** | 系统 Edge `--headless=new` + Node 24 全局 `WebSocket` 直连 CDP，不装 puppeteer | 我只用了 90 行就搭好了原型的截图+报错检查（`prototype/tools/shoot.mjs`） |
| **发布即构建** | `build.mjs` 白名单复制 + 引用校验 + 体积上限 | 防止"忘提交一个文件"和最吓人的"发布包 300 MB" |

**我的原型里已经把这套跑通了**：`node tools/shoot.mjs` 一条命令，自动发车、装 5 把不同武器、跑 16 秒、截 4 张图、打印运行状态、收集所有 console 报错。

## 11. 最后：三个判断

**① 这个底座对你的游戏值多少钱？**
值 **1.5 周**（轨道 + 投影 + UI 外壳 + 工程链路），外加一个**免费的数据管道**（如果你打算用真实城市做废土地图）。它不值的是"战斗"——那是你游戏 60% 的工作量，底座一点忙帮不上。

**② 玩法上最值得赌的一条是什么？**
**"前方尸群拖慢列车"**。它把"开火车"和"打丧尸"两件事从"并排"变成"互为因果"：你必须清轨道才能跑得快，跑得快才能少挨咬，少挨咬才能撑到下一站。原型里这条已经跑通了——你会在表里看到"前方 14"变红的时候本能地想把机枪挪到车头。

**③ 最大的风险是什么？**
不是技术，是**"照抄经营游戏的手感"**。底座的每一个数字都在为"看得懂"服务，而动作游戏要为"打得到"服务。两者冲突的地方（实体生命周期、时间轴、碰撞）必须毫不犹豫地重写，哪怕看起来"底座已经有类似的东西"。
