# 发布指南：把《末世列车》放到公网

这个仓库里的游戏是**纯静态站点**（一个 `index.html` + `css/` + `js/`，零构建），
所以任何静态托管都能跑。以下是三种常见做法。

---

## 先选一个

| 方案 | 优点 | 缺点 | 适合 |
| --- | --- | --- | --- |
| **GitHub Pages** | 零配置、和仓库天然绑定、免费 | `*.github.io` 在中国大陆**经常超时/不稳**；只支持静态 | 开源展示、给外国人看 |
| **Cloudflare Pages** | 全球 CDN、免费额度大、可以绑域名、构建快 | 国内访问依赖 Cloudflare 线路，**不保证快**；需要注册 | 想给国内朋友玩、想要自己的域名 |
| 任意静态服务器 / OSS | 完全可控 | 要自己配 HTTPS、备案（国内） | 正式运营 |

> 两个都开没有坏处：GitHub Pages 当"源码仓库自带演示"，Cloudflare 当"能打开的链接"。

---

## A. Cloudflare Pages（推荐给国内访问）

### A1. 连接 Git 仓库（推荐，push 即自动部署）

1. 打开 https://dash.cloudflare.com/ → 左侧 **Workers & Pages**
2. **Create** → 第二个标签页 **Pages** → **Connect to Git**
3. 授权 GitHub，选中仓库 **`nanji0710/GDD_moshi`**
4. 构建配置（**这四项是唯一容易填错的地方**）：

   | 字段 | 填什么 |
   | --- | --- |
   | Project name | `last-train`（随便） |
   | Production branch | `main` |
   | Framework preset | **None** |
   | Build command | **留空**（不要填 `npm run build`） |
   | Build output directory | **`prototype`** |

5. **Save and Deploy** → 第一次构建约 20 秒
6. 成功后地址是 `https://last-train.pages.dev`（或你起的名字）

之后每次 `git push` 到 `main`，它都会自动重新部署。

### A2. 直接上传（不接仓库，最快）

1. 本地先打包（仓库里已经有现成的）：`release/last-train-prototype.zip`
   - 这个包**只含游戏本体**：`index.html` + `css/` + `js/` + `assets/models-data.js` + `404.html` + `_headers`，白名单 29 项 / 324,403 B（316.8 KiB），sha256 `2231c4f8…`；重出命令：`node tools/package-release.mjs`（同一输入逐字节一致）
   - 3D 模型数据只有 `assets/models-data.js` 这一份（40 个 `.glb` 源文件在仓库 `models/glb/`，不进部署目录）
2. Cloudflare 控制台 → **Workers & Pages** → **Create** → **Pages** → **Upload assets**
3. 把 zip 拖进去（或解压后拖文件夹）→ **Deploy site**
4. 得到 `https://xxx.pages.dev`

> 上传包的根目录必须是 `index.html` 所在的那一层——`last-train-prototype.zip` 已经是对的结构，**不要再套一层 `prototype/`**。

### A3. 绑自己的域名（可选）

Pages 项目 → **Custom domains** → **Set up a custom domain** → 输入域名
→ 按提示在 Cloudflare DNS 里加一条 `CNAME` 指向 `xxx.pages.dev`（域名本来就在 Cloudflare 的话是一键）。

---

## B. GitHub Pages（本仓库已经配好）

仓库自带 `.github/workflows/pages.yml`，**只发布 `prototype/` 目录**（站点根就是游戏）。

1. 仓库 **Settings → Pages**
2. **Source** 选 **GitHub Actions**
3. **Actions** 页 → `Deploy prototype to GitHub Pages` → **Run workflow**
4. 站点：https://nanji0710.github.io/GDD_moshi/

> 如果 Source 下拉里没有 `GitHub Actions`，退而求其次：Source = `Deploy from a branch`，
> Branch = `main`，Folder = `/ (root)`。仓库根目录的 `index.html` 会自动跳到 `prototype/index.html`。

## C. 发布前检查清单

- [ ] 双击 `prototype/index.html` 能直接玩（file:// 协议下不报错、0 个 404；进关不下载模型，首次切 3D 才异步加载，视网速约 1–5s）
- [ ] `cd prototype && node tools/smoke.mjs` 全绿（181/181，CI 里也会跑，见 `.github/workflows/smoke.yml`）
- [ ] `cd prototype && node tools/perf.mjs`：首屏同步传输 ≈ 481,922 B / 26 请求，DCL ≈ 0.09s（83–107ms，4× CPU 降速）；进关静置 2.5s 不应出现 models-data 请求
- [ ] 手机横屏能开（HUD 会自动缩放，但站台抽屉在窄屏需要滚动）
- [ ] 站点是 **HTTPS**（两个平台都自动给）
- [ ] 首屏同步 < 1 MB（实测 470.6 KiB：js + css + index.html；1.3MB 模型数据首次切 3D 时才异步加载）
- [ ] 没有把 `prototype/tools/shots/`（33 张截图）或 `*.log` 打进发布包

## D. 缓存与更新

- 静态资源文件名**没有 hash**，所以更新后浏览器可能用到旧 js。
  测试时用 `Ctrl+F5` 强制刷新；正式运营建议给 `js/*.js` 加版本查询串（如 `?v=3.8`）。
- Cloudflare 的缓存默认遵循源站；Pages 每次部署是新版本，几分钟内全球生效。

## E. 如果国内访问仍然慢

Cloudflare 免费版走的是国际线路，国内体验"能开但不算快"。真要给国内用户做，按成本从低到高：

1. 绑一个**国内访问友好的域名**（同样是 Cloudflare，但换了 Anycast 线路）
2. 用 **国内对象存储 + CDN**（阿里云 OSS / 腾讯云 COS + CDN），需要**域名备案**
3. 打包成 **Electron / Tauri 桌面版**直接分发（最省事，也不需要备案）
