## 0. 一页摘要

**真正值钱的只有三样：**

1. **弧长参数化**。整条线路压成一维 `pts[] + cum[]`，任何物体（列车、车厢、车头灯、丧尸）只存一个标量 `d` 就能反解 `{x, y, 朝向}`。这是「列车沿铁路推进」最正确的几何抽象（util.js:89-114），**无脑抄**。
2. **车厢沿曲线展开**。`trainSpan → joints[k]` 完整回答了「整列车在弯道上怎么摆」，还顺带解决端点夹紧（车尾永不越界）（agents.js:202-211 + 257-275）。这就是车顶武器挂点的坐标系基础。
3. **梯形速度三段反解**。`legTime`/`legSpeed`/`legFrac` 三个函数不到 30 行（metro.js:453-457、agents.js:74-87），把「给定区间长度和计划用时 → 反解峰值速度 → 按时间求里程」做对了，含零长度除零保护、减速段终点倒推不漂移。**一个字符都不用改。**

**最危险的一点：它根本没有实体间交互。** 我在 `js/` 全目录 grep `hp|health|damage|collide|collision|hitbox` 与 `fixedStep|accumulator|substep`，**双双零命中**。所有「车与车」「列车与行人」关系都是统计关系或位置压制关系，不是物理关系。动作游戏的核心循环（打中了吗、扣血了吗、会不会撞墙）**一行都不能抄，必须从零建**。

**判断：几何层抄 80%，运动层抄 60%，实体层抄 15%，战斗层抄 0%。**

## 1. 路网与轨道几何

**三层数据结构**（metro.js:8）：`net { stations{}, segments{}, lines{}, nextId }` → `net` 纯数据可 JSON 序列化，不含任何缓存几何。关键决策：**「编辑态」与「编译态」分离**——`segment.pts` 存玩家手画的折线拐点，真实轨道由「车站 + 拐点」切线连续化后重采样得到。改一个拐点，整段运行结构重建。

**从控制点到折线：Hermite 而非贝塞尔**（metro.js:64-95）。每个控制点先算切线：首尾用相邻弦方向，中间点取「前弦 + 后弦」单位向量和再归一化（metro.js:70-76）。每小段用三次 Hermite 基插值（metro.js:88-90）：`P(t) = h00·P1 + h10·T1·L + h01·P2 + h11·T2·L`，其中 `h00=2t³-3t²+1, h10=t³-2t²+t, h01=-2t³+3t², h11=t³-t²`，**切线被乘上弦长 `L`**（metro.js:83），所以控制点间距差很多也不会过冲打结——比固定张力 Catmull-Rom 稳。采样步长 `STEP = 0.12` 格 = 30 m（metro.js:6、102）。

**站台直线段**：`segControl`（metro.js:51-61）在两端各插一个辅助控制点，距离 `Lp = min(platformHalfM/CELL_M, len/4)`（metro.js:54），并强制首末两段画直线（metro.js:82）。原因：停站时车厢必须与站台平行，否则车门对不上。新游戏要做「到站停车、丧尸从站台涌上来」，这个约束同样成立。

**弧长参数化——整套系统的地基**（util.js:89-114）：

```js
cum[0] = 0;  cum[i] = cum[i-1] + dist(pts[i-1], pts[i])     // 前缀和
posAt(pts, cum, d) -> { x, y, a, i, f }
  二分找 lo 使 cum[lo] <= d < cum[lo+1]
  t = (d - cum[lo]) / (cum[lo+1] - cum[lo])      // seg>0 ? ... : 0 兜底
  x,y = lerp(pts[lo], pts[lo+1], t)
  a   = atan2(dy, dx)                            // 朝向直接由线段方向给出
```

三个必须抄的细节：**① 两端越界保护**（util.js:98-105）——`d<=0` 取 `pts[1]-pts[0]` 的朝向，`d>=末点` 取末段朝向；漏了这一步端点朝向会变成 `atan2(0,0)=0`，车头突然转向右方。**② `seg>0` 兜底**防止两站重合时 NaN。**③ 同时返回 `i` 和 `f`**，让调用方能线性插值任意逐点属性——底座用它插值轨面高度 `heightAt`（agents.js:380-384）；新游戏可同样把「路况颠簸」「伏击密度」挂成与 `pts` 等长的数组，用 `(i,f)` 插值。

**线形约束与两条限速链**（config.js:81-102）：

| 参数 | 值 | 用途 | 位置 |
|---|---|---|---|
| `minRadiusM` / `warnRadiusM` | 250 / 400 m | 低于此半径不允许建造 / 警告 | config.js:93-94 |
| `latAccel` | 0.8 m/s² | 弯道横向加速度上限 → 反解弯道限速 | config.js:84 |
| `maxGrade` | 0.03 | 最大坡度，算坡道长度用 | config.js:97 |
| `levelM` | 地下 -15 / 地面 0 / 高架 12 **m** | 轨面**物理**高程 | config.js:98 |
| `height` | 地下 -0.11 / 地面 0 / 高架 0.075 **格** | 轨面**视觉**高度 | config.js:101 |
| `platformHalfM` | 70 m | 站台直线段半长 | config.js:96 |
| `vmax` | 地下 22 / 地面 19 / 高架 22 m/s | 区间最高速 | config.js:82 |

**几何限速**（metro.js:130-140 + 492）：用「相隔约 60 m 的三点外接圆」估曲率半径 `R = abc/(2·area2)`，再 `vmax = min(vmax, max(8, sqrt(latAccel·minRadiusM)))`。250 m 半径 → `sqrt(0.8×250) ≈ 14.1 m/s ≈ 51 km/h`，远低于 19-22 m/s。**弯道真的会让车慢下来**，这是天然的玩法节奏点。⚠️ **单位陷阱**：`g.pts/cum/lenC` 是格，`g.lenM/minRadiusM` 是米，只靠命名后缀 `M`/`C` 区分——**新游戏务必统一成米**，这是底座最容易埋 bug 的地方。

**坡度：物理用米，视觉用格，两套各算各的。** `rampNeed`（metro.js:158-161）= `|高程差| / maxGrade`，纯物理用 `levelM`；`heightProfile`（metro.js:163-177）生成视觉高度数组 `hs[]`：**站台范围内高度恒定**（车厢与站台齐平），**站台外才用 smoothstep 爬坡**。这个「平台恒定 + 两端平滑过渡」的写法对动作游戏同样有用（桥上战斗区高度恒定，桥头才起伏）。但注意 `hs` 单位是格、是美术参数，**不能当物理高度用于弹道**。

**`compile()`：唯一编译入口**（metro.js:459-516），产出 `C = { stations, sIndex, segs, lines, routes, topo }`：

```js
C.sIndex = Map(stationId → 0..N-1)
C.segs.set(id, { seg, g: segGeom(...), h: heightProfile(...) })    // 几何+高度，缓存
for (rt of lineTopo.routes) {                                      // 一个 line 可有多条运行方案
  pts=[]; hs=[]; stopDist=[0]; legLenM=[]; legSec=[]; legSeg=[]
  for (each seg of rt.segs) {
    p = cs.g.pts; h = cs.h
    if (ref.rev) { p = p.reverse(); h = h.reverse() }               // 反向区段靠反转数组
    pts.push(...); stopDist.push(length)                           // 每个停站的弧长位置
    vmax = mc.vmax[type]
    if (isFinite(g.minRadiusM)) vmax = min(vmax, sqrt(latAccel*minRadiusM))   // 弯道限速
    legLenM.push(Lm); legSec.push(legTime(Lm, vmax, accel))         // 每段时间
  }
  cars = min(沿线所有站的车厢上限)                                  // 编组受最小站台限制
  cum  = cumLen(pts)
  cycleSec = loop ? runSec + dwell*n : 2*runSec + 2*dwell*(n-2) + 2*turnaround
}
```

**`rt` 字段清单（新游戏最该抄的结构）**：`pts`(格) 合并折线 / `cum`(格) 前缀弧长 / `hs`(格·视觉) 逐点轨面高度 / `stopDist`(格) 每个停站的弧长位置，长度=站数 / `legLenM`(**米**) 每个区间真实长度 / `legSec`(秒) 每个区间计划用时 / `legSeg` 每区间对应的 segment / `cars` 编组节数 / `cap` 总定员 / `lenM` 全线米 / `runSec`,`cycleSec`(秒) 单程与完整周转 / `loop`,`branch` / `stIds`,`stIdx`。注意 `stopDist` 与 `legLenM` 分开存是刻意的：前者是「在线路折线上的位置」（格，用于定位），后者是「这一区间多长」（米，用于速度曲线）——**建议原样保留这个拆分**。

**该不该沿用**：`net/line/segment` 三层 → 砍成 `line + station[]`，但「编辑/编译分离 + 产物缓存」必须留；Hermite 切线连续化 → 若铁路是程序生成，这套就是现成的地形贴合方案，**抄**；`cum`+`posAt` → **无脑抄**；弯道限速 → **保留**（弯道减速 = 丧尸追得上的时刻）；坡度 → 可砍，除非做「失控下坡」桥段；`compile()` → 抄思路重写实现。

## 2. 列车运动学

**双时间轴——本作最反直觉的设计**（agents.js:59-62）：

```js
const sp  = game.speed > 0 && !game.jumping && !game.pending ? CFG.time.speeds[game.speed-1] : 0;
const dtv = dt * sp * CFG.time.visualPerSec;    // ← 视觉时间
this.vt += dtv;
```

| 时间轴 | 换算 | 谁在用 |
|---|---|---|
| 游戏时钟（minute/day） | `dt × speed / 2.5 × 60` 分钟（game.js:146） | 客流、经济、日结算 |
| 视觉时间 `dtv` | `dt × speed × 24` 秒（config.js:21） | **列车位置、车门、行人** |

`dt` 来自 `requestAnimationFrame` 并夹到 ≤0.1 s（main.js:241）；`speeds = [1,3,8]`（config.js:20）；`visualPerSec = 24`；`secPerHour = 2.5`（config.js:19，即 **一天 = 60 秒真实时间**）。

**结论：列车不按游戏时刻跑，按视觉时间跑。** 一条 `cycleSec = 3000`（50 分钟）的线，1× 下只要 125 秒真实时间跑完一整圈，而游戏时钟只走了 0.9 小时。这是为「好看」牺牲一致性：若真按游戏时刻跑，一天 60 秒里列车只走 1/50 圈，屏幕上几乎不动。**新游戏的列车是玩法主体，必须与战斗共用同一条时间轴——这是「要补什么」的第一条。**

**梯形速度曲线：三个函数，三种用途。**

① `legTime(Lm, vmax, a)`——已知区段长度，算该走多久（metro.js:453-457）：

```js
const dAcc = vmax*vmax/a;                       // 加速段+减速段总距离
if (Lm >= dAcc) return Lm/vmax + vmax/a;        // 够长：梯形（有匀速段）
return 2 * Math.sqrt(Math.max(1, Lm)/a);        // 太短：纯三角形，跑不到 vmax
```

`Math.max(1, Lm)` 防 `Lm=0` 时开出 `T=0`，让下游除零。

② `legSpeed(Lm, T, a)`——已知长度和用时，反解实际峰值速度（agents.js:74-77）：

```js
const disc = a*a*T*T - 4*a*Lm;
return (a*T - Math.sqrt(Math.max(0, disc))) / 2;   // 梯形 Lm = v*T - v²/a 解一元二次取小根
```

**这是整套运动系统自洽的关键**：`legSec` 来自调度（会被弯道限速、调速、事故拖延改动），列车必须按**给定时间**跑完，而不是按**给定速度**跑完，否则时刻表错位。

③ `legFrac(t, T, Lm, v, a)`——区间内经过时间 → 已走比例（agents.js:78-87）：

```js
if (t <= 0) return 0;
if (t >= T || Lm <= 1e-9) return 1;                       // 零长度区间直接到站，避免 0/0
const ta = v/a;
if (t < ta)            d = 0.5*a*t*t;                     // 加速
else if (t < T - ta)   d = 0.5*a*ta*ta + v*(t-ta);        // 匀速
else { const tr = T-t; d = Lm - 0.5*a*tr*tr; }            // 减速：从终点倒推
return clamp(d/Lm, 0, 1);
```

**减速段用「终点倒推」而非「当前位置正推」，是这套代码最漂亮的一处**：`d = Lm - 0.5a(T-t)²` 保证 `t=T` 时精确落在 `Lm`，不会因浮点累积让列车停在站台前后 3 米。正推写法跑一百圈之后必然漂移。

**状态机：一条腿（leg）四种状态**（agents.js:193-235）。位置由纯函数 `trainPos` 给出：

```js
trainPos(t, out):
  L = legs[t.leg]
  f = t.t < 0 ? 0 : legFrac(min(t.t, L.T), L.T, L.Lm, L.v, accel)
  d = L.d0 + (L.d1 - L.d0) * f          // 反向腿就是 d1→d0
  out.fwd = L.d1 >= L.d0                 // 朝向由 d0/d1 大小关系给出
```

| 状态 | 判据 | 含义 |
|---|---|---|
| `run` | `0 <= t.t < L.T` | 区间运行 |
| `dwell` | `t.t >= L.T` | 到站停站 `L.dwell` 秒 |
| `hold` | `t.t < 0` | 起点等候发车，`t.t = -(due - now)` 负倒计时 |

`phase`（agents.js:219-235）的关键：**车门角度是算出来的不是存的**——`door = min(开门曲线, 关门曲线)`，停稳 2 秒后开、开 2 秒、距发车 6 秒开始关（`DOOR = {delay:2, open:2, closeLead:6, close:2, walk:3, gap:1.1}`，agents.js:217）。末端站还要把「等发车」时间算进 `until`（agents.js:229），否则会出现「门先关、等 40 秒、又开门」。注释明说「**不另存动画状态**，暂停、加速、跳月、换视图与读档后按同一时刻得到同一结果」（agents.js:214-216）。**纯函数式做法非常值得抄**——新游戏的「到站开门 = 丧尸涌上来的窗口期」若用存的状态机，暂停/存档/快进一定错乱。

**多列车：分组 → 解析式铺满 → 间隔控制**（若只做玩家一列车，整段可砍）。

- **分组**（agents.js:88-135）：按 `routeKey + dir + leg数` 建 `group`。线路一改 key 就变，老车原地淡出、新线重新铺满（agents.js:120-134：位置差 `> 0.3 格` 就淡出而非瞬移）。
- **解析式铺满**（agents.js:137-148）：`need = ceil(cycle/h)`，第 `i` 辆从起点在 `i·h` 前发车，然后把「发车时刻」换算成「此刻该在第几腿的什么时刻」：

```js
let off = i*h, leg = 0;
while (leg < legs.length && off >= legs[leg].T + legs[leg].dwell) { off -= ...; leg++ }
trains.push({ leg, t: off })          // ← 不是"跑一遍模拟"，是直接算出来
```

**不用预热**：读档、开局、改线后立刻是稳定运行状态。这个技巧对丧尸波次同样适用——不模拟前 20 波怎么积累的，直接按 `wave × density(t)` 算此刻场上该有多少只。

- **间隔控制**（agents.js:162-165 + 184-188）：到站后检查 `now >= lastDep + h`，没到点就把 `t.t` 设成负数进 `hold`，避免串车。

**★ 伪代码 B：A 站到 B 站的最小调度循环**（剥掉客流/经济/双时间轴）：

```js
// ===== 常量（新游戏重新取值）=====
const ACCEL = 0.55;      // m/s²  末日重载机车，比地铁 0.9 慢
const DWELL = 12;        // 秒    到站停站（同时是「站台战斗」窗口） / TURNAROUND = 40 秒折返

// ① 区间用时（metro.js:453-457）
function legTime(Lm, vmax, a) {
  const dAcc = vmax*vmax/a;
  return Lm >= dAcc ? Lm/vmax + vmax/a : 2*Math.sqrt(Math.max(1,Lm)/a);
}
// ② 反解峰值速度（agents.js:74-77）
function legSpeed(Lm, T, a) {
  const disc = a*a*T*T - 4*a*Lm;
  return (a*T - Math.sqrt(Math.max(0, disc))) / 2;
}
// ③ 时间→里程比例（agents.js:78-87）
function legFrac(t, T, Lm, v, a) {
  if (t <= 0) return 0;
  if (t >= T || Lm <= 1e-9) return 1;
  const ta = v/a; let d;
  if (t < ta)          d = 0.5*a*t*t;
  else if (t < T - ta) d = 0.5*a*ta*ta + v*(t-ta);
  else { const tr = T-t; d = Lm - 0.5*a*tr*tr; }    // 终点倒推，不漂移
  return clamp(d/Lm, 0, 1);
}
// ④ 编组：A→B→折返→A
function makeLeg(k, rev, dwell) {
  const Lm = legLenM[k];                                   // 米
  const T  = legTime(Lm, Math.min(VMAX, curveLimit(k)), ACCEL);
  return { k, rev, d0: stopDist[rev ? k+1 : k], d1: stopDist[rev ? k : k+1],   // 起终点弧长（格）
           T, Lm, dwell, v: legSpeed(Lm, T, ACCEL) };
}
function makeTrain(n) {                                    // n = 站数
  const legs = [];
  for (let k = 0; k+1 < n; k++) legs.push(makeLeg(k, false, k+1===n-1 ? TURNAROUND : DWELL));
  for (let k = n-2; k >= 0; k--) legs.push(makeLeg(k, true,  k===0     ? TURNAROUND : DWELL));
  return { legs, leg: 0, t: 0 };
}
// ⑤ 每帧推进（agents.js:169-192 精简版）；dt 必须是「游戏秒」，不是渲染秒
function tickTrain(tr, dt) {
  let rem = dt, guard = 0;
  while (rem > 0 && guard++ < 50) {          // guard 防超大 dt 死循环
    const L = tr.legs[tr.leg], end = L.T + L.dwell;
    if (tr.t + rem < end) { tr.t += rem; rem = 0; break; }
    rem -= (end - tr.t);
    tr.leg++; tr.t = 0;
    onArrive(tr, tr.leg - 1);                          // ★ 到站事件钩子
    if (tr.leg >= tr.legs.length) tr.leg = 0;          // 一圈跑完
  }
}
// ⑥ 位置查询（纯函数，任何时候可重算）
function trainDistance(tr) {
  const L = tr.legs[tr.leg];
  const f = tr.t < 0 ? 0 : legFrac(Math.min(tr.t, L.T), L.T, L.Lm, L.v, ACCEL);
  return { d: L.d0 + (L.d1 - L.d0)*f, fwd: L.d1 >= L.d0 };
}
```

**被剥掉的东西**（对照 agents.js:149-192）：`group` 分组与 `g.h/need/lastDep`（只留 1 列车就全删）、`alpha/dying`（**保留**，列车被炸毁时有用）、`hold` 状态（**保留语义**，改名「等待发车」，做「下一站还有 N 秒」HUD）、`dtv` 双时间轴（**删掉**）、`legLoad/paxCount`（**删掉**，换成「本站丧尸数量」）。

## 3. 车厢编组与「车顶挂点」定位（核心一节）

**三个常数决定整列车的几何**（agents.js:202）：`CAR_M = 20`（单节车厢长度，米）、`GAP_M = 1.6`（车厢之间视觉缝隙，米）。

**极其重要、很多人看错的一点：`GAP_M` 不参与弧长计算。** 整列车长 `Lt = CAR_M × cars / CELL_M`（agents.js:206），**车厢中心间距就是 20 m**，一节不少。1.6 m 的缝在**画的时候**每节车厢两端各缩进 4% 得到（agents.js:301-305）：

```js
const gapPx = nCar > 1 ? Math.min(0.5, carGap/carLen) : 0;   // = 1.6/20 = 0.08
const carPath = (k) => {                                     // agents.js:302-305
  const a = joints[k], b = joints[k+1], g0 = k>0 ? gapPx/2 : 0, g1 = k<nCar-1 ? gapPx/2 : 0;
  ctx.moveTo(a.x + (b.x-a.x)*g0, a.y + (b.y-a.y)*g0);
  ctx.lineTo(b.x + (a.x-b.x)*g1, b.y + (a.y-b.y)*g1);
};
```

所以 **逻辑节距 20 m（无缝），视觉车长 18.4 m（有缝）**。妙处：车厢总长恒等于 `cars × 20`，不会因为「加个缝」导致列车整体变长越界，同时视觉上又能看出分节。**新游戏必须照抄这个约定**，否则武器挂点会和玩家看到的车厢对不上。

**`trainSpan`：整列车在曲线上的展开**（agents.js:204-211，完整实现见下文伪代码 A2）：

```
total = rt.cum[末];  Lt = max(CAR_M*cars/CELL_M, 0.12);  dir = pos.fwd ? 1 : -1
head = pos.d + dir*Lt/2;  rear = pos.d - dir*Lt/2
if (!loop) {  lo=min(head,rear); hi=max(head,rear)
              sh = lo<0 ? -lo : (hi>total ? total-hi : 0);  head+=sh; rear+=sh }   // ★ 整列车平移，绝不截断
```

两个关键细节：**① `pos.d` 是整车中心弧长，不是车头**（agents.js:200 注释：停站时车体中心对准站台中心），对称计算因此极简；**② 端点整体平移**：车头冲出终点线时**整列车往回平移**，而不是车头停在终点车尾继续前进——保住了「车厢永不脱轨」的硬约束，视觉上像进站超了一点又退回。

### ★ 伪代码 A：给定弧长 s，求车厢中心世界坐标与朝向

```js
/* 坐标系：世界坐标，单位「格」（新游戏建议改米）
   依赖：posAt（util.js:95-114）、lerpAt（agents.js:380-384）*/

// ---------- A0. 弧长 → 折线上的点与切线 ----------
function posAt(pts, cum, d, out) {
  const n = pts.length; out = out || {};
  if (n === 1 || d <= 0) {                      // 越界：起点（必须给朝向！）
    const b = n > 1 ? pts[1] : pts[0];
    out.x = pts[0][0]; out.y = pts[0][1];
    out.a = Math.atan2(b[1]-pts[0][1], b[0]-pts[0][0]);
    out.i = 0; out.f = 0; return out;
  }
  if (d >= cum[n-1]) {                          // 越界：终点（绝不能 atan2(0,0)）
    out.x = pts[n-1][0]; out.y = pts[n-1][1];
    out.a = Math.atan2(pts[n-1][1]-pts[n-2][1], pts[n-1][0]-pts[n-2][0]);
    out.i = n-2; out.f = 1; return out;
  }
  let lo = 0, hi = n-1;                         // 二分
  while (hi - lo > 1) { const m = (lo+hi)>>1; if (cum[m] <= d) lo = m; else hi = m; }
  const span = cum[hi]-cum[lo];
  const t = span > 0 ? (d-cum[lo])/span : 0;    // 零长度保护
  const a = pts[lo], b = pts[hi];
  out.x = a[0] + (b[0]-a[0])*t;
  out.y = a[1] + (b[1]-a[1])*t;
  out.a = Math.atan2(b[1]-a[1], b[0]-a[0]);
  out.i = lo; out.f = t; return out;
}
// ---------- A1. 逐点属性插值（轨面高度等） ----------
function lerpAt(attr, p) {                      // attr: 与 pts 等长的 Float32Array
  const i = p.i, f = p.f || 0;
  const a = attr[i], b = attr[Math.min(attr.length-1, i+1)];
  return a + (b-a)*f;
}
// ---------- A2. 整列车展开：所有接缝的弧长 ----------
function trainSpan(rt, sCenter, cars, dir) {    // agents.js:204-211
  const total = rt.cum[rt.cum.length-1];
  const Lt = Math.max(CAR_M * cars / METERS_PER_UNIT, 0.12);
  let head = sCenter + dir*Lt/2, rear = sCenter - dir*Lt/2;
  if (!rt.loop) {
    const lo = Math.min(head,rear), hi = Math.max(head,rear);
    const sh = lo < 0 ? -lo : (hi > total ? total - hi : 0);
    head += sh; rear += sh;                     // 整列车平移，绝不截断
  }
  return { head, rear, dir, Lt, total, loop: rt.loop };
}
function jointDist(sp, k, cars) {               // 第 k 个接缝弧长（0=车头，cars=车尾）
  return k === cars ? sp.rear : sp.head - sp.dir * k * (CAR_M / METERS_PER_UNIT);
}
// ---------- A3. ★核心：第 k 节车厢的姿态 ----------
function carPose(rt, sCenter, k, cars, dir) {
  const sp = trainSpan(rt, sCenter, cars, dir);
  const dA = wrap(jointDist(sp, k,   cars), sp.total, sp.loop);   // 前接缝
  const dB = wrap(jointDist(sp, k+1, cars), sp.total, sp.loop);   // 后接缝
  const pA = posAt(rt.pts, rt.cum, dA, {});
  const pB = posAt(rt.pts, rt.cum, dB, {});
  /* ===== 曲线上的车厢：按「弦」处理，不按弧 =====
     底座做法（agents.js:302-305）：车体就是接缝 A→B 的直线段。
     弯道上每节车厢各自是直的一条，接缝处形成折角 —— 正是真火车的样子。 */
  const cx = (pA.x + pB.x)/2, cy = (pA.y + pB.y)/2;
  // 朝向两种取法：
  //  (a) 弦方向   —— 两端精确落在轨道上，但急弯上短车厢朝向有台阶感（画车体用这个）
  //  (b) 中点切线 —— 朝向平滑，但两端会略微离开轨道（炮塔转向用这个）
  const pM = posAt(rt.pts, rt.cum, (dA+dB)/2, {});
  let angChord = Math.atan2(pB.y-pA.y, pB.x-pA.x), angTan = pM.a;
  if (dir < 0) { angChord += Math.PI; angTan += Math.PI; }        // 统一朝车头
  return {
    cx, cy, dA, dB,
    ang: normAng(angChord),          // 画车体
    angSmooth: normAng(angTan),      // 炮塔/武器
    hA: lerpAt(rt.hs, pA), hB: lerpAt(rt.hs, pB),
    chordLen: Math.hypot(pB.x-pA.x, pB.y-pA.y)
  };
}
// ---------- A4. 车顶武器挂点 ----------
// u ∈ [-0.5,+0.5] 沿车厢归一化位置（-0.5 车头端，0 正中）
// side ∈ [-1,+1] 横向位置（-1 左缘，+1 右缘）—— 用于「两侧各装一挺机枪」
// CAR_H 车体高（格）、CAR_W 车宽（格）
function carMount(rt, sCenter, k, cars, dir, u, side, CAR_H, CAR_W) {
  const pose = carPose(rt, sCenter, k, cars, dir);
  const pA = posAt(rt.pts, rt.cum, wrap(pose.dA, rt.cum[rt.cum.length-1], rt.loop), {});
  const pB = posAt(rt.pts, rt.cum, wrap(pose.dB, rt.cum[rt.cum.length-1], rt.loop), {});
  let ux = pB.x-pA.x, uy = pB.y-pA.y;
  const L = Math.hypot(ux,uy) || 1; ux /= L; uy /= L;
  const nx = -uy, ny = ux;                                   // 法向（左为正）
  const t = 0.5 + u;                                         // 沿车厢参数
  const wx = pA.x + (pB.x-pA.x)*t + nx*side*(CAR_W/2);
  const wy = pA.y + (pB.y-pA.y)*t + ny*side*(CAR_W/2);
  const pAt = posAt(rt.pts, rt.cum, pose.dA + (pose.dB-pose.dA)*t, {});
  const wh = lerpAt(rt.hs, pAt) + CAR_H;                     // 挂点高度 = 轨面 + 车体
  return { wx, wy, wh, fwdX: ux, fwdY: uy, nx, ny, ang: pose.angSmooth };
}
// ---------- A5. 世界 → 屏幕（2.5D 投影，render.js:355-361）----------
// R.M 2×2 视图矩阵, R.z 缩放, R.hs 每单位高度像素
function toScreen(R, wx, wy, wh) {
  return { x: R.ox + (R.M[0]*wx + R.M[1]*wy)*R.z,
           y: R.oy + (R.M[2]*wx + R.M[3]*wy)*R.z - (wh||0)*R.hs };
}
// ---------- A6. 每帧：算所有车厢与挂点 ----------
function updateAllMounts(rt, train) {
  train.poses = [];
  for (let k = 0; k < train.cars; k++) {
    const p = carPose(rt, train.sCenter, k, train.cars, train.dir);
    p.k = k;
    p.mounts = train.weapons[k].map(w =>
      carMount(rt, train.sCenter, k, train.cars, train.dir, w.u, w.side, CAR_H, CAR_W));
    train.poses.push(p);
  }
  return train.poses;
}
// ---------- 小工具 ----------
const wrap = (d, total, loop) => loop ? ((d%total)+total)%total : clamp(d, 0, total);
const normAng = (a) => { while (a > Math.PI) a -= 2*Math.PI;
                         while (a < -Math.PI) a += 2*Math.PI; return a; };
```

**与真实代码的对应关系**：A0 = util.js:95-114（**可原样抄，含越界保护**）；A1 = agents.js:380-384；A2 = agents.js:204-211；A3 接缝循环 = agents.js:268-275（底座直接投到**屏幕坐标**，这里改成纯世界坐标）；A3 弦方向 = agents.js:302-305；**A4 底座没有，是本文核心新增**；A5 = render.js:355-361；A6 = agents.js:258-275 简化。

**曲线车厢的三个「近似直线段」层次**（任务点名要讲透）：

- **层次 1：车体本身是直的。** 20 m 车厢当弦，半径 `R` 的圆上矢高 `≈ 100/(2R)`：`R=250 m` 时 **≈ 0.2 m**，视觉完全不可见。**这个近似安全，可照抄。**
- **层次 2：接缝在曲线上，整列车是折线。** 每节车厢两端都真的贴在轨道上，所以「脊柱」跟着弯道折（agents.js:266 注释「沿实际轨道曲线取点，转弯时各节车厢分别转向」）。
- **层次 3：LOD —— 远景直接画一根直线**（agents.js:267）：`nCar = z >= 14 ? rt.cars : 1`，缩放小于 14 时 `joints` 只算车头车尾两个点。**但武器挂点不能跟着退化**：远景可以不画武器，但子弹发射源必须仍按 20 m 节距算，否则「远看打得准，近看打不准」。

**底座已有的三种「挂点」，结构上等价于车顶挂点，可直接参照**：车门（agents.js:335-344）沿弦取 `f ∈ {0.3,0.7}`、法向偏 `±(width/2 + 1.6·door)`；车窗（agents.js:320-325）沿弦 `0.16→0.84` 画粗线；车头灯（agents.js:327-332）用 `head - joints[1]` 归一化得前向再偏移 `width*0.25`；代表性乘客（agents.js:346-367）用车厢内 `f∈{0.3,0.7}` 与左右侧在「门→站台」间 lerp。

注意 agents.js:354 的技巧：**用 hash 而非随机数决定「这个乘客从哪节车厢的哪个门上车」**，`U.hash2(stop, j, 5)` 中 `stop = t.id*131 + t.leg*17` 是停站标识。每次重画同一次停站，乘客位置完全一样，**不会闪烁**。新游戏的「丧尸从哪节车厢爬上来」同理：**用 `(波次id, 丧尸序号)` 做 hash 种子，不要用 `Math.random()`。**

## 4. 实体与群体 AI

底座有三类实体，生命周期模式高度一致。**共同点：没有一个会死，也没有一个会撞。**

**汽车 `cars`**（agents.js:519）：`{ link, dir, s, v, alpha, kind, lane, color, ang, dying, dead }`，`s` 是路段内里程（格）。

| 阶段 | 做什么 | 位置 |
|---|---|---|
| 生成 | 遍历可见路段，`target = min(lenKm*30, vol/sp*lenKm*vis)`，不够就补 | agents.js:499-527 |
| 移动 | `c.v` 用 `dt*2` 时间常数 lerp 到目标速度；`c.s += c.v*dtv` | agents.js:422-434 |
| 换段 | 到路段末端 → 按流量加权随机挑下一条 | agents.js:435-451 |
| 销毁 | 目标段出视野→`dead`；数量超标→`dying`；`alpha` 归零后移除 | agents.js:448、523-525、464-468 |
| **视野外** | `if (!show) for (c of cars) c.dying = true; return;` **全部淡出清空** | agents.js:469 |

⚠️ **本作最重要的实体哲学：实体是视觉产物，不是模拟产物。** 镜头移开就消失，回来按流量重生成。全城只有 `CFG.perf.maxCars = 320` 辆「代表性」汽车（config.js:216），而真实日均车流几十万次。**新游戏能抄一半**：屏幕外丧尸**可以冻结不更新**（省性能），但**绝不能删除**——玩家会发现「跑出去再回来，丧尸没了」；且丧尸必须有身份（血量、武器归属、死亡标记），不能每次重生成。

**行人 `peds`**（agents.js:608）：`{ pts, cum, len, s, v, alpha, st, color }`，`pts/cum` 是从车站 600 m 内的步行路径。生成时（agents.js:582-610）**不是实时寻路**，而是从 `acc.trees[k]`（车站 k 的步行最短路树，sim.js:688-694）里随便挑个顶点、沿 `pred` 回溯到车站得到折线。**预计算一次树，每个行人只是「选终点 + 回溯」，O(路径长度) 而非 O(图)。** 这就是「伪寻路」的核心技巧，非常适合丧尸：预计算（每个热点跑一次 Dijkstra 得 `pred` 树）→ 运行时（挑目标顶点，沿 `pred` 回溯出折线，按弧长匀速走）。代价是只能走到「热点」附近，不能任意两点寻路——但对「丧尸往列车涌」来说，**热点就是列车经过的轨道**，正好够用。

**街道行人 `walkers`**（agents.js:658）：`{ link, side, off, s, dir, len, v, alpha, color }`，连路径都没有，就在一条路的一侧来回走（agents.js:626-662）。数量由 `WALK_ACT[小时] × WALK_LU[用地]` 决定（agents.js:624-625，两张 24 长度查表数组），上限 `maxWalkers = 120`。**这张 24 小时活动强度表最该抄**：一行数组表达「凌晨没人、早晚高峰挤、商业区晚上还热闹」的全部信息。新游戏的丧尸密度同样用两张表：`WAVE_ACT[24]`（活跃度）× `ZONE_LU[11]`（区域危险度）。

**空间索引四层，各司其职**：

| 索引 | 结构 | 键 | 用途 | 位置 |
|---|---|---|---|---|
| `carIndex` | `Map<int, car[]>` | `2*(2*link+dir)+lane` | **按「路段+方向+车道」分桶**，跟车排序 | agents.js:530-531 |
| `carBuckets` | `Geo.buckets(road.links, 8, W, H)` | 网格 | **静态**：路段外包框分桶，视野查询 | geo.js:164-174 |
| `visibleRoads` | `{key, ids}` | 视野矩形字符串 | 视野缓存：矩形不变不重查 | agents.js:497-498 |
| `bucket(C)` | `Map<"i:j", entity[]>` | 网格（每帧重建） | **动态**：渲染排序（车/人混排后按 y 排） | agents.js:671-695 |

`Geo.buckets` 骨架（geo.js:164-183）：要素外包框跨几个桶就 push 进几个桶；`query` 遍历矩形覆盖的桶并用 `Set` 去重。**静态索引省 CPU 但只适合不变的东西**（绑定 road.links），**动态索引适合会动的实体但每帧 O(n)**。新游戏要补的是：丧尸沿轨道逼近，天然就是「按轨道弧长段分桶」，比网格更好，O(1) 就能找到「我前方 20 m 内有哪些丧尸」。

**适不适合丧尸群？逐项体检**：

| 丧尸群需要 | 底座有 | 缺/补 | 难度 |
|---|---|---|---|
| 寻路 | ✅ 预计算最短路树 + `pred` 回溯（sim.js:688-694） | ❌ 只有到固定热点的树，无任意两点 A* | 中（`U.Heap` 现成，util.js:48-86） |
| 避障/拥挤 | ⚠️ 只有「同车道按 s 排序后强行压位置」（agents.js:455-462） | ❌ 无转向力、无分离行为、无软碰撞 | 中 |
| **碰撞检测** | ❌ **完全没有**（grep 零命中） | 全部 | **高（从零建）** |
| **生命值/伤害** | ❌ **完全没有**（grep 零命中） | 全部 | 中 |
| 目标选择 | ⚠️ 只有「按流量加权随机挑下一条路」（agents.js:446） | 无「最近威胁」「优先级」 | 低 |
| 数量控制 | ✅ 硬上限 `maxCars 320 / maxPeds 180 / maxWalkers 120` | 上限是「代表性」的，不是「性能」的 | — |
| 视野外 | ⚠️ 直接删除（agents.js:469） | 只能冻结，不能删 | 低 |
| 确定性 | ✅ `U.hash2` 稳定随机（util.js:15） | — | — |
| 群体化 | ⚠️ `counts` Map 只做数量统计（agents.js:579-580） | 无 boids/群聚 | 中 |

**结论：底座提供的是一套「有位置、有速度、没有身体」的实体系统——是运动的壳，不是战斗的肉。**

```js
model.step(budget)                                // 交通模型增量迭代
```

`clock.minute` 是**浮点数**不是整数，这样 0.4 小时 = 24 分钟这种非整数推进不丢精度。`endDay`（game.js:158-180）是所有日结系统的唯一入口：经济结算 → 事故判定 → 日期推进 → 月结 → 破产判定。**新游戏的「波次结算」应挂这里，不要散落各处。**

**分时段权重 `W`：双周期混合**（sim.js:1274-1285）返回 `{ p0,w0,s0, p1,w1,s1, svc, prof }`：`p0/p1` 相邻两个时段（AM/MD/PM/EV），`w0/w1` 权重和归一，`s0/s1` 该时段在 24 小时曲线上的相对强度，`svc` 是否在运营时段，`prof` 当前出行强度。在时段边界（每小时 45 分后、15 分前）做过渡插值，避免「8:00 整客流瞬间翻倍」的台阶。所有逐时段数组读取都走 `a*W.w0*W.s0 + b*W.w1*W.s1`（如 sim.js:1286-1288）。**这是最廉价的真实感技巧：一行 `a*w0 + b*w1` 替代一整个插值系统**，丧尸活跃度、光照、环境音密度都可以共用同一个 `W`。

**新游戏三样东西挂在哪**：

| 新需求 | 挂载点 | 底座对应物 |
|---|---|---|
| 波次 wave | 自建 `WaveDirector.update(dt)`，放在 `game.update` 之后 `agents.update` 之前 | 无；最接近 `updateCars` 的 target 数量控制（agents.js:509-513） |
| 昼夜 | `game.clock` + `Model.weights` | sim.js:1274-1285，直接用 W 结构 |
| 列车到站事件 | `tickTrain` 的 `onArrive()`（agents.js:180 的 `t.leg++` 之后） | 唯一自然事件点，纯函数驱动，暂停/存档安全 |
| 武器开火 | 新系统，`agents.update` 之后 `render` 之前 | **无，必须自建**（见 §8） |
| 伤害结算 | 新系统，开火之后 | **无，必须自建**（见 §8） |

## 8. 反例：这套系统天生不适合动作/射击的地方

**每条都标了「不要照抄什么」与「要补什么」。**

**8.1 没有碰撞，也没有任何「实体占位」概念。** 全目录 grep `collide|collision|hitbox` 零命中。唯一近似的是 `agents.js:455-462` 的跟车压制：`if (list[i].s > list[i-1].s - gap) { list[i].s = list[i-1].s - gap; ... }`——**它直接把位置改掉**，没有力、没有反弹、没有伤害、没有「撞到了」这个事件。而且**列车与汽车/行人完全无交互**：`updateTrains` 从头到尾没读过 `this.cars`/`this.peds`，列车开过去汽车直接穿模。
> **不要抄**：位置钳制当碰撞。**要补**：① 分层碰撞矩阵（丧尸↔列车、丧尸↔丧尸、子弹↔丧尸、丧尸↔障碍），至少「圆-矩形」，别上 SAT；② 碰撞必须有**响应**（推开丧尸防叠坨、阻挡列车防穿模）；③ **CCD 连续检测**——列车 20 m/s、子弹 300 m/s，60 fps 下每帧位移 0.3 m / 5 m，必须做线段扫掠，否则子弹穿怪。

**8.2 没有生命值、没有伤害、没有死亡。** grep `hp|health|damage` 零命中。实体消失只有两种原因：`alpha <= 0`（淡出结束）和 `dead`（逻辑淘汰）。**连「死亡」这个概念都不存在**——汽车不是撞坏了，是「镜头移开了所以不画了」。
> **不要抄**：`alpha → dying → 删除` 这套视觉生命周期当实体生命周期。**要补**：① 实体状态机 `spawn→active→dying→dead`，`dying` 仍参与碰撞（尸体挡路）但不可再被命中；② **单一伤害入口** `damage(amount, type, source)`，中间走护甲/抗性/暴击，末尾统一判死，**不要让每把武器自己减血**；③ 死亡可追溯（谁杀的、什么武器、多少伤害），否则做不了击杀统计/经验/成就。

**8.3 客流是统计式的，不是实体。** 一列 6 节编组、定员 1440 人的地铁，车上有多少人是**算出来的一个数字**（`legLoad`，agents.js:239-244），画面上最多画 8 个小圆点（`paxCount`，agents.js:237）；真正的客流是矩阵、skim、收敛迭代（sim.js:886-1096）。这对经营游戏是对的（几万人不可能逐个模拟），对动作游戏**完全错误**：玩家打中一个丧尸必须真的死，不能只是「本区间客流下降 0.3」；清空一节车厢必须「真的没了」，不能「统计上少了」。
> **不要抄**：任何「用比率代替个体」的做法。**要补**：真正有身份的实体池；数量上限靠**对象池 + 视距剔除**（远处降频更新但**不销毁**），不能靠按密度生成代表性个体。

**8.4 逻辑帧率不固定。** `const dt = Math.min(0.1, Math.max(0, (t-last)/1000))`（main.js:241），全项目**没有任何固定步长累加器**（grep `fixedStep|accumulator|substep` 零命中）。帧率 144→20 fps 时 `dt` 从 0.007 变到 0.05。对经营游戏没问题（时间本就连续），对动作游戏是灾难：子弹积分用变 dt → 帧率变化时弹道不同、命中率忽高忽低；碰撞用变 dt → 低帧率一帧位移 15 m 直接穿怪；开火逻辑写在帧回调里 → 高帧率玩家射速更快。
> **不要抄**：`dt` 直通所有系统。**要补**：`accumulator += dt; while (accumulator >= FIXED_DT) { stepSimulation(FIXED_DT); accumulator -= FIXED_DT }`，`FIXED_DT = 1/60`，物理/战斗/AI 一律固定步长，渲染用插值 `render(accumulator/FIXED_DT)`。底座唯一做对的是 `dt` 上夹 0.1 s（防切标签页回来跳 10 秒），**这个上限要保留**。

**8.5 寻路缺失：只有「预计算树 + 回溯」。** 底座「寻路」分两层：站外步行（每个车站跑一次 Dijkstra 存 `pred` 树，sim.js:655-695，行人从树里挑点回溯）与换乘（`metroTree` 对每站跑 Dijkstra，sim.js:209-236）。**没有**：任意两点 A*、动态障碍（新出现的墙/火/尸体）、NavMesh/格子图分层寻路、流场。
> **要补**：① **一维优先**——丧尸默认沿「轨道弧长 + 横向车道」运动，零寻路成本，**强烈推荐这是主方案**；② 需要绕障碍时用**流场（flow field）**：以列车为中心算一次 Dijkstra 得每格「下一步方向」，所有丧尸共享，比每只跑 A* 便宜两个数量级，且天然产生「成群涌来」的效果；③ 反向用 `U.Heap`（util.js:48-86）。

**8.6 逻辑与渲染耦合。** 最直接的证据是 `drawTrains`（agents.js:245-372）**一边画一边把结果写回实体**：`t.sx/t.sy/t.drawn`（278）、`t.segType/t.hh`（282）、`t.door/t.state`（369）。也就是说**不渲染这些字段就不存在**——点击选中列车、声音播放都依赖 `t.sx/t.sy`，一帧不画这些功能就坏。同理 `Agents.update` 第 67 行先更新列车，第 68 行 `if (!R.view) return;`——没有视图时汽车行人全停。
> **不要抄**：`update(dt, game, R)` 这种把渲染器传进逻辑层的签名。**要补**：① 逻辑层**禁止**引用渲染层，位置/朝向/血量必须在 `update` 算好、渲染只读；② 屏幕坐标转换留在渲染层，逻辑层只处理世界坐标；③ 需要屏幕相关剔除时传**视锥数据** `{x0,y0,x1,y1}`，不要传整个 `R`。

**8.7 其他不适合照抄的地方**

| 问题 | 事实 | 新游戏怎么办 |
|---|---|---|
| 世界是「格」，1 格 = 250 m | config.js:12；车长 20 m 只有 0.08 格 | 改**米制**（1 单位 = 1 米），否则一切尺寸除以 250，浮点精度与可读性都差 |
| 高度是视觉参数不是物理量 | `hs` 单位格、`levelM` 单位米，两者不换算 | 补真实 y/z 轴（哪怕伪 3D），弹道要能算高度差 |
| `net` 用 `JSON.parse(JSON.stringify())` 克隆 | metro.js:9 | 实体带函数/引用时此路不通；用结构化克隆或手写 `deepClone` |
| 实体裸对象 + 数组 `splice` 删除 | agents.js:466 | 上千实体时 `splice` O(n) 且 GC 抖动；用**对象池 + 交换删除**（`arr[i]=arr[--n]`） |
| 每帧 `new` 临时对象 | agents.js:250 一次 6 个 `{}` | 60 fps 下是 GC 压力；**预分配复用**（底座已复用 `this._joints`，agents.js:257） |
| `Math.random()` 直接用 | agents.js:446、515、592 | 影响可复现性（回放/联机/测试）；战斗相关一律走**种子化随机** |
| 没有「命中反馈」通道 | 无 | 需要 hitstop、击退、伤害数字、屏幕震动、音效，且必须能被打断/缓存 |
| 没有「武器数据」概念 | 无 | 武器要独立成数据：射程/射速/伤害/散布/弹药/过热/转向速度；挂点只是位置 |
| 没有确定性/回放/联机 | 无 | 若要联机或录像，从第一行代码就做确定性模拟（固定步长 + 整数随机 + 状态哈希） |

**一句话总结反例：底座的每一个实体都是「视觉证据」，新游戏的每一个实体必须是「物理事实」——底座删除实体的原因是「看不见了」，新游戏删除实体的原因必须是「它死了」。**

## 9. 给主设计师的 5 条结论

**1. 抄「弧长」，别抄「格」。** 整套底座最值钱的抽象是「一切物体只用一维标量 `d` 定位」（util.js:89-114 + `cum`）。不用写任何寻路就能让丧尸、子弹、车厢共享同一坐标系，而「丧尸追列车」直接退化成「两个标量比大小」。但 1 格 = 250 m 是给城市地图用的，**新游戏第一件事就是把单位改成米**，否则车厢长 0.08 个单位、武器射程 0.4 个单位，调试时全是浮点误差。

**2. 车厢沿曲线展开可以照抄，但「车顶挂点」必须自己加，而且第一版就要加。** `trainSpan → joints[k] → 弦`（agents.js:204-211 + 302-305）已把「多节车厢在弯道上怎么摆」做到位，包括端点整体平移，直接抄。但底座**没有挂点概念**，只有车门/车窗/车头灯三种装饰性挂点（agents.js:320-344）。新游戏的核心操作是「在车厢顶部装不同武器」，所以挂点坐标系（§伪代码 A4 `carMount`）**是第一个要写对的函数**，它决定后面所有射击手感。特别提醒：**逻辑节距恒为 20 m，1.6 m 缝隙只在渲染时缩进**（agents.js:301），抄错会导致「看着装在前端，子弹从后半节出膛」。

**3. 一定要删掉双时间轴，这是新游戏最容易继承的架构债。** 底座两条时间轴：游戏时钟（`secPerHour=2.5`，一天 60 秒，config.js:19）与视觉时间（`visualPerSec=24`，config.js:21），列车按后者跑（agents.js:61），导致「跑完一整圈，游戏时钟只过 0.9 小时」。对经营游戏没问题，对动作游戏意味着**玩家瞄准的和列车实际所在的不是同一时刻**。新游戏必须只有一条时间轴，列车运动、丧尸移动、子弹飞行、武器冷却全用同一个 `dt`，且**这个 `dt` 必须是固定步长的累加值**（§8.4），不能用 `requestAnimationFrame` 的原始间隔。

**4. 底座的这三样东西一个都不要抄：统计式客流、视野外删除、位置钳制当碰撞。** `legLoad`（agents.js:239）与 `paxCount`（agents.js:237）把几千人压成一个数字，直接违背「打中就该死」的核心契约；`if (!show) for (c of cars) c.dying = true`（469）会让「跑出去再回来丧尸没了」；`list[i].s = list[i-1].s - gap`（460）把碰撞变成位置赋值，没有任何事件产出。这三处必须**从零重写**：实体池（有身份、有血量、死了才删）、视距降频（远的不更新但不销毁）、真实碰撞（分层矩阵 + 连续检测 + 响应）。

**5. 真正该抄的是「纯函数位置」和「解析式铺满」这两个思路，它们能省掉半个月调试。** `trainPos`/`phase`（agents.js:193-235）证明「位置与状态由 `(leg,t)` 纯计算得出、不存动画状态」可以做到——暂停、加速、读档、跳帧全部免费，也让「到站开门 = 站台战斗窗口」天然对齐。`fillGroup`（agents.js:137-148）证明「不模拟历史、直接按公式铺满当前应有状态」可以做到——丧尸波次完全可以照办：不模拟前 20 波怎么积累的，直接按 `wave × density(t)` 算此刻场上该有多少只、分布在哪，然后补齐差额。**这两条加起来，就是新游戏第一版可以砍掉一半状态机代码的理由。**
