### 1.2 `CM.U.h()` 实现说明

签名：`h(tag, props, ...children) → HTMLElement`，实现只有 22 行（`js/util.js:280-301`）。它不是虚拟 DOM，**每次调用都直接 `document.createElement` 并返回真实节点**，没有 diff、没有 patch、没有 key。

**props 特殊键**（`util.js:283-292`）：

| 键 | 行为 | 行号 |
|---|---|---|
| `class` | `el.className = v`（字符串拼接由调用方做，不支持数组） | 286 |
| `style` | 值为对象；`--x` 开头走 `style.setProperty`，其余 `style[k]=v`；为字符串则原样忽略（未处理） | 287 |
| `on*` | 值为函数时 `addEventListener(k.slice(2), v)`，**大小写敏感**（`onclick`→`click`，`onmouseenter`→`mouseenter`） | 288 |
| `html` | `el.innerHTML = v`（唯一的内联 HTML/SVG 入口） | 289 |
| `text` | `el.textContent = v` | 290 |
| 其它 | `setAttribute(k, v === true ? '' : v)` | 291 |
| `null / undefined / false` | **整条跳过**，所以可以写 `cond ? h(...) : null` 做条件渲染 | 285 |

**children 处理**（`util.js:297-301`）：

- 从第 3 个参数起收集；`null / false / undefined` 跳过（注意 `Element.append(null)` 会写入字符串 `"null"`，`appendChild(null)` 直接抛错，作者在 `ui.js:309` 特意注释过这个坑）
- **数组递归展平** → 数组就是 fragment，不需要 `DocumentFragment`
- `string / number` → `createTextNode`；其它一律当 `Node` 直接 `appendChild`
- 所以 `h('div', null, [a, b])` 与 `h('div', null, a, b)` 完全等价，页面里两种写法混用（`pages.js:120,1345`）

**不支持的能力**（新游戏必须补齐的部分）：

| 能力 | 现状 | 绕过方式（仓库里的真实写法） |
|---|---|---|
| SVG | ❌ 无 `createElementNS`，`h('svg')` 只会得到 `HTMLUnknownElement` | 全部走 `html:` 或 `innerHTML`：`ui.js:65`（日期环）、`pages.js:1210`（进度环）、`icons.js:145-147`（`CM.icon` 用 span + innerHTML） |
| fragment / key / diff | ❌ | 数组代替 fragment；列表全量重建 |
| `className` / `dataset` / property | ❌ 只认 `class`，一律 `setAttribute` | 用 `setAttribute('data-*')`；输入框初值可用，**后续更新必须 `el.value = x`**（`pages.js:184-187`） |
| 事件委托参数 | ❌ | 手写 `data-*` + `closest`（`ui.js:42,327-328,346-348`） |

**可直接抄到新游戏的最小实现（约 60 行，补齐了 SVG / class 数组 / dataset / ref / property）**：

```js
// ui/dom.js —— 新游戏可直接使用；比原版多出的能力已在注释标 ★
const SVG_NS = 'http://www.w3.org/2000/svg';
const SVG_TAGS = new Set(['svg','g','path','circle','rect','line','polyline','polygon',
  'text','ellipse','defs','linearGradient','radialGradient','stop','use','clipPath']);

export function h(tag, props, ...kids) {
  const el = SVG_TAGS.has(tag)
    ? document.createElementNS(SVG_NS, tag)          // ★ SVG 命名空间
    : document.createElement(tag);
  if (props) for (const k in props) {
    const v = props[k];
    if (v == null || v === false) continue;          // 条件渲染
    if (k === 'class' || k === 'className') {
      el.setAttribute('class', Array.isArray(v) ? v.filter(Boolean).join(' ') : v); // ★ 数组
    } else if (k === 'style') {
      if (typeof v === 'string') el.setAttribute('style', v);
      else for (const s in v) s.startsWith('--') ? el.style.setProperty(s, v[s]) : (el.style[s] = v[s]);
    } else if (k === 'dataset') {
      for (const d in v) if (v[d] != null) el.dataset[d] = v[d];                 // ★ dataset
    } else if (k.length > 2 && k[0] === 'o' && k[1] === 'n' && typeof v === 'function') {
      el.addEventListener(k.slice(2).toLowerCase(), v);                          // ★ 大小写宽容
    } else if (k === 'html') el.innerHTML = v;
    else if (k === 'text') el.textContent = v;
    else if (k === 'ref' && typeof v === 'function') v(el);                      // ★ 取引用
    else if (k in el && typeof v !== 'string') el[k] = v;                        // ★ value/checked/disabled
    else el.setAttribute(k, v === true ? '' : v);
  }
  appendKid(el, kids);
  return el;
}

function appendKid(el, kids) {
  for (const c of kids) {
    if (c == null || c === false || c === true) continue;
    if (Array.isArray(c)) { appendKid(el, c); continue; }
    el.appendChild(c instanceof Node ? c : document.createTextNode(String(c)));
  }
}

// 挂载：一次创建、后续只替换内容（避免 innerHTML='' 丢焦点）
export function mount(root, view) { root.replaceChildren(); appendKid(root, [view]); }
```

> 注意最后一行：原版页面切换用 `this.rBody.innerHTML = ''`（`ui.js:1224`）+ 重建，代价是输入框焦点、中文输入法组合状态、滚动位置全部丢失，作者为此写了三处补丁（`ui.js:170-177` 失焦后补刷新、`ui.js:1742` 编辑中不重绘、`ui.js:1800`/`tools.js:512` 的 `isComposing` 检查）。新游戏如果也用「整页重建」，请直接 `replaceChildren` 并保留滚动位置，别再补三处补丁。

### 1.3 渲染模型：没有重渲染机制，只有分层手工刷新

这是理解整套 UI 的核心。它**既不是声明式，也不是脏检查**，而是「**一次性建骨架 + 定时改文本 + 事件里局部重建**」三件套。

**(a) 骨架只建一次**：`buildChrome()`（`ui.js:51-216`）在 `new UI(R)` 里调用（`ui.js:39`），把 13 个根节点、若干胶囊、按钮全部建好并把**子节点引用存成字段**（`this.pills[key] = {el, v, k, badge}`，`ui.js:59`），后续只改 `textContent` / `innerHTML`。

**(b) 三档刷新节拍**（`ui.js:418-454`）：

```js
const now = performance.now();
if (force || now - this.lastTick > 250) {          // 4Hz：顶栏数值 + live 闭包 + 统计窗口
  this.lastTick = now; this.updateTop();
  for (const f of this.live) { try { f(); } catch (e) {} }   // 页面内「活数据」
  ...
}
if (force || now - this.lastSlow > 1000) {         // 1Hz：横幅、草案栏、自动保存
  this.lastSlow = now; this.updateBanner(); this.renderDraftbar(); ...
}
```

**(c) 页面 = 纯函数 + 整块重建**：`openPage(kind,id,opts)`（`ui.js:1169-1178`）压栈 → `renderPage(anim)`（`1206-1234`）调用 `this['page_' + kind](id)`（`1214`）拿到 `{title, el}`，清空 `rBody` 后 append。命名约定 `page_build / page_station / page_line / page_finance / page_tasks / page_saves / page_help / page_data`（实现分散在 `pages.js:110,300,441,626,682,746,1296,1337,1353`、`pages_company.js`、`pages_staff.js`、`pages_ops.js`）。

**(d) 唯一的"订阅"是 `this.live` 闭包数组**：

```js
UI.prototype.liveText = function (fn, cls) {        // ui.js:1279-1284
  const el = h('span', { class: cls || '' }, '');
  const upd = function () { el.textContent = fn(); };
  upd(); this.live.push(upd);
  return el;
};
```

- 页面构建时 `this.live.push(fn)`（如 `pages.js:138-146` 把四个 stat 卡的更新函数推进去）
- `tick()` 每 250ms 全跑一遍（`ui.js:439`），用 `try/catch` 吞掉"页面已变化"的异常
- `renderPage` 开头 `this.live = []`（`ui.js:1209`）清空；`closePanel` 也清（`ui.js:1186`）

**(e) 防重绘全靠手写 key 字符串**——这是最容易出错的地方：

| 位置 | 守卫 | 说明 |
|---|---|---|
| `ui.js:923` | `_dbKey = draft.ver \| can.ok \| funds \| pred.state \| undo.length \| redo.length` | 草案栏 |
| `ui.js:823-825` | `_toKey = [tool, chain, lineChoice, buildType, stationSize, draft.ver, y].join('\|')` | 工具选项条 |
| `ui.js:702-704` | `_bannerKey = JSON.stringify(items)` | 横幅 |
| `ui.js:732-738` | `_tipKey = title + '\|' + lines.join('\|')` | 地图 tooltip |
| `ui.js:509,526,549` | `_satTipT / _covTipT / _goalT` 各 1s 节流 | 胶囊 tooltip（读 localStorage 的项） |
| `ui.js:434-438` / `ui.js:170-177` | `pageDailyStale` / `_pendingRefresh` | 客流算完自动补一次重绘 / 输入框内不刷新，`focusout` 后 300ms 补 |

**(f) 数值滚动**：`tweenNum(el, from, to, fmt)`（`ui.js:620-631`）用 `el._tw = {to}` 标记防重入，450ms 三次方缓出；`reducedMotion` 时直接赋值。资金飘字 `moneyFloat`（`633-643`）往 `#fxLayer` 塞一个绝对定位 `div`，1.7s 后 `remove()`。

**结论**：这套模型对「面板式、低频、局部」的 UI 够用且极其轻量（零依赖、零构建），但**没有"状态→视图"的单一入口**。新游戏如果沿用，必须把 `live` 换成显式的 `store.subscribe(fn)`，否则每加一个面板就要再手写一个 `_xxxKey`。

### 4.2 交互与状态

- **两个选中态**：`当前车厢`（左栏高亮）与 `当前挂点`（中栏高亮）；选中挂点后右栏卡片才出现「安装到选中挂点」按钮。
- **推荐"点→点"而非拖拽**：底座里**没有任何 HTML5 拖放先例**（全仓库 `dataTransfer`/`draggable` 出现 0 次），画布上的"拖"是自己用 pointer 事件实现的（`tools.js:95-134`）。从 DOM 卡片拖到 canvas 挂点，需要自己处理跨层指针捕获 + 命中测试 + 拖影，**收益小风险大**。第一阶段用"点武器 → 点挂点"，与 `showLinePicker` 的"点一次弹浮层，再点一项"完全同构（`ui.js:863-903`）。
- **改装即草案**：所有变更先进 `pending` 草案（复用 `game.js:465-534` 的 draft 语义），底部栏显示「N 项 · 费用 X · [撤销][重做][放弃][确认改装]」，`Esc` 先退草案（`ui.js:904-916` 的阶梯）。
- **即时预估**：每次变更重算 stats 并刷新底部预估条（可抄 `sizeCards` 里的 `.size-diff` 升级对比块，`ui.js:1395-1401`）。
- **冲突不阻塞编辑，只阻塞确认**：`canConfirm` 返回 `{ok, reason}`（`game.js:525-534`），`renderDraftbar` 用它禁用按钮并把 `reason` 写 `data-tip`（`ui.js:938`）。

### 5.3 命中测试：屏幕空间缓存，不是世界坐标重投影

这是**新游戏做"点挂点"最该抄的一点**。渲染时顺手把屏幕坐标存进数组，拾取时直接线性扫（半径判定），不做世界→屏幕反算：

```js
// 渲染阶段（render.js:2108-2119）
this.stPx = [];
for (let i = 0; i < C.stations.length; i++) {
  ...
  const p = this.P(s.x, s.y, h);                 // 世界→屏幕
  this.stPx.push({ x: p.x, y: p.y, r: r, id: s.id });   // 存屏幕坐标 + 屏幕半径
  ...
}
// 拾取阶段（render.js:3142-3151）
Renderer.prototype.pickStation = function (sx, sy) {
  let best = null, bd = 1e9;
  for (const p of this.stPx) {
    if (!p) continue;
    const d = Math.hypot(p.x - sx, p.y - sy);
    if (d < p.r + 7 && d < bd) { bd = d; best = p.id; }   // r + 7px 容错
  }
  return best;
};
```

同类实现：`pickSegment`（容差 7px 的线段距离，`render.js:3152-3163`）、`pickLink`（按 4 格网格分桶后再算多边形距离，`3176-3183`）、`Follow.pick`（移动物体，用渲染时写回的 `tr.sx/tr.sy` + 帧号 `tr.drawn` 判断"是否本帧画过"，半径 13px，`follow.js:77-86`）。

> **对挂点的直接启示**：挂点是**随列车移动**的目标，必须用 `Follow.pick` 这套「渲染时写回屏幕坐标 + 帧号」的做法；不能像车站那样缓存一次就不更新。且 `Follow.pick` 里 `R.frame - tr.drawn > 1` 的过期判断（`follow.js:81`）能天然避免"点到已经被裁掉的挂点"。

### 5.4 草案预览：beginLive / liveEdit / endLive

拖动类编辑不进 undo 栈，而是：

1. 按下时 `g.beginLive()` → `d.liveSnap = JSON.stringify(d.net)`（`game.js:488`）
2. 每次移动 `g.liveEdit(fn)` → 直接改 `d.net`、`d.ver++`、发 `draftLive` 事件（`game.js:489`）
3. 抬起时 `g.endLive(changed)` → 有变化才把快照推进 undo，无变化则 `JSON.parse` 回滚（`game.js:490-495`）

配套 UI：`ui.js:381-382` 监听 `draft`/`draftLive` 事件，`lastDraftChange` 时间戳 + `tick` 里 1.2s 空闲后才自动重算预测（`ui.js:448-453`，避免拖动时每帧跑重算）。**这套"拖动期间只标记、松手才结算预测"的节流是新游戏必须抄的**。

## 6. 交互细节清单（值得抄 / 别抄）

### 6.1 快捷键体系

`Tools.prototype.onKey`（`tools.js:511-568`）是整个游戏唯一的键盘入口（没有第二处 `keydown`，除 `ui.js:339` 的"任意键隐藏 tooltip"）。分层清晰：

2. **模态优先**：`ui.blocking()` 时只处理 `Esc`（`522`）。
3. **浮层优先**：线路选择框打开时数字键选中、Esc 关闭（`525-528`）。
4. **组合键**：`Ctrl+Y / Ctrl+Shift+Z` 重做、`Ctrl+Z` 撤销、`Ctrl+Enter` 确认建设（`530-532`）。
5. **跟随态特化**：`H` 收界面、`Esc` 退出跟随（`535-538`）。
6. **单键工具与视图**：`空格` 暂停、`1/2/3` 倍速、`V/B/L/E/X` 工具、`T` 2.5D、`U` 地下、`G` 统计、`K` 线网图、`/` 搜索、`N` 主题、`M` 音效、`F` 全图、`+/-` 缩放、`Backspace` 退转弯点/撤销、`Enter` 结束绘线、`Esc` 阶梯（`540-562`）。
7. **按住方向键平移**：`keys` 集合 + `tick(dt)` 里按 `600*dt` 像素/秒平移（`570-579`）。注意 `blur` 时清空按键集合（`59`），否则切窗口回来会一直平移。

### 6.2 Esc 阶梯（最值得抄的交互设计）

`UI.prototype.escape`（`ui.js:904-916`）是一个**优先级从高到低的 11 级逃生梯**，每级只做一件事：

### 7.1 先看数据

### 7.2 六个具体问题

**① 一个类被拆到 6 个文件里，165 个方法平铺在一个原型上。**
`UI.prototype.page_tasks` 在 `pages.js:1212`，`page_staff` 在 `pages_staff.js`，`page_ops` 在 `pages_ops.js`，`page_company` 在 `pages_company.js`，`showStart/showMapSelect` 在 `screens.js`。想看"任务页用到哪些 helper"必须 grep 全目录。`page_*` 的命名约定（`ui.js:1214` 的 `this['page_' + kind]`）是唯一的隐式接口，**没有类型、没有契约、没有注册表**——新增一个页面靠"记得在 6 个文件之一里写一个同名方法"。

**② 手工 DOM 更新 + 手写 key 守卫 = 刷新逻辑与业务逻辑纠缠。**
`renderDraftbar` 的守卫是 6 个字段拼字符串（`ui.js:923`）；`renderToolOpts` 是 7 个字段（`823`）。漏一个字段 → 状态变了但界面不更新；多一个字段 → 每次刷新都重建 DOM 丢焦点。仓库里为此付出的代价是可见的：`pageDailyStale`（`434-438`）、`_pendingRefresh`（`170-177`）、`editing` 集合（`1742`）、`isComposing`（`1800`）——**四处补丁都在解决同一个问题："整块重建会打断用户输入"**。

**③ `innerHTML = ''` + 重建导致的三类状态丢失。**
页面渲染固定三连（`ui.js:1224-1227`）：清空 → append → 恢复 `scrollTop`。恢复不了的：输入框焦点与选区、`<input type=range>` 的拖动中状态、`<details>`/滚动容器的中间态、CSS 动画进度。`showSaveManager` 用 `editing` 集合整个跳过重绘（`1742`）是一种"止血"，但列表里其它行的重命名会被一起冻住。

**④ 事件与定时器的生命周期靠"约定"而非机制。**
- 全局委托只在构造函数里装一次（`ui.js:42,327,336,346`）——这部分是干净的
- 但浮层每次打开都往 `window` 装监听：菜单（`ui.js:1460-1463`）、搜索（`1638-1643`）。移除靠"下一次 pointerdown 自己移除"，而 `escape()` 关闭菜单（`ui.js:909`）时**不会移除**那个监听，要等下一次任意点击才回收
- `setTimeout` 全都不保存句柄：`toast`（`723`）、`moneyFloat`（`642`）、`showLinePicker` 的退出动画（`902`）、`confirm` 无。切换地图/退出对局时这些回调仍会执行（`main.js:208-236` 的 `endGame` 只 `remove()` 了容器，没有 `clearTimeout`）
- 一次 `renderPage` 产生的闭包数量 ≈ 页面的 `onclick` 数（任务页 20+），随 DOM 一起被 GC，但 `this.live` 必须显式清（`ui.js:1209`），漏一处就会持续调用已卸载元素的 `textContent`

**⑤ 界面缩放的实现方式把布局计算污染到 JS 里。**
`zoom: var(--uiz)`（`style.css:127`）让 `getBoundingClientRect()` 返回缩放值，于是每个需要定位的地方都要 `/ uiz`：`ui.js:222-228`（feed 居中）、`243`（断点判断）、`style.css` 里 12 处 `calc(... / var(--uiz,1))`。漏一处就是错位。同时 `zoom` 会让 `offsetWidth` 与 CSS 像素不一致，`fitHud` 的全部测量（`ui.js:253-286`）都建立在这个一致性上。

**⑥ 现代 CSS 选择器当逻辑用。**
`#app:has(#stats:not(.hidden)) .pausechip { opacity: 0 }`（`style.css:364`）、`:has(#netmap…)`（`690`）、`:has(#legendCard…)`（`1231`）。三处"某窗口打开时隐藏某提示"的逻辑写在 CSS 里，JS 侧无法感知；再加一处就要再写一条 `:has`。


三条硬规则：

1. **`game/` 里不许出现 `document`**——原作的 `game.js` 做到了（它只 `emit` 事件），但 `ui.js:371-408` 把 10 个事件监听塞在一个 45 行的函数里，新游戏把这段拆成 `ui/bindings/*.js`，每个面板自己订阅自己关心的字段。
2. **一个面板 = 一个函数 + 一份 `state → view` 的纯映射 + 一个 `dirty` 集合**。不要 `_dbKey` 拼接，用 `store.select(['draft.ver','funds'])` 之类的最小订阅。
3. **列表用 keyed 复用**（哪怕只有 30 行）：车厢 7 节、挂点 8 个、武器 12 把，都是固定长度、会反复改的小列表，整块重建完全没必要，且会毁掉拖拽/输入状态。

## 9. 给主设计师的 5 条结论

**1. 抄 `h()` + 令牌 + 6 个组件块，你就有 80% 的界面；抄 165 个方法平铺的组织，你会用两周换来一个不敢改的 136KB 文件。**
地基在 `util.js:280-301`（22 行）、`style.css:2-101`（100 行令牌与按钮）、`style.css:250-328`（面板/折叠/kv/stat/callout/冲突卡）。这三处加起来不到 200 行，能撑起"改装 + 波次 + HUD + 设置"全部界面。而 `pages.js` 的 36 个 UI 方法（13 个面板页）与 `UI.prototype` 的 165 个方法，是可读性的负资产——新游戏按 §7.3 的目录重写，不要试图"改一改原作"。

**2. UI 的第一优先级不是好看，是"解释数值为什么变"。**
这套 UI 最被低估的设计是 `updateTop` 里满意度那段（`ui.js:508-520`）：数值旁边直接写"下滑中；车厢拥挤 12%；主因：拥挤 −3.2、票价 −1.1"。玩家不用翻面板就知道该改什么。新游戏照这个规格做三处：装甲旁边写"主因：撞击 −12 / 感染 +3"、弹药旁边写"消耗 4/s，补给 6/s"、战力预估旁边写"火力 +28%，持续 −26%"——**只在 HUD 上加一个数字，不给原因，等于没做 HUD**。

**3. 车厢改装不要做拖放，做"点武器 → 点挂点 → 看预估 → 确认"。**
底座里 `dataTransfer/draggable` 出现 **0 次**，唯一现成的"拖动"是画布上自己写的 pointer 状态机（`tools.js:95-134`）。跨 DOM→canvas 拖拽要新写指针捕获、拖影、命中测试、失败回弹，工作量是"点两次"的 5 倍，收益只是手感。而"点两次"的所有零件都现成：`showLinePicker` 的锚定浮层（`ui.js:863-903`）、`.size-card` 的选择卡（`ui.js:1373-1403`）、`.size-diff` 的前后对比（`ui.js:1395-1401`）、`renderDraftbar` 的"草案 N 项·费用 X·确认"（`ui.js:919-940`）。**先把"点两次 + 预估 + 草案确认"跑通，再考虑拖放。**

**4. 把"改装"做成草案（可撤销、可放弃、确认才生效），而不是即时生效。**
这是这套底座最成熟的交互模式：`beginLive/liveEdit/endLive`（`game.js:488-495`）+ `undo/redo`（`496-505`）+ `canConfirm` 返回 `{ok, reason}`（`525-534`）+ 底部草案栏（`ui.js:919-940`）+ 放弃确认（`1009-1016`）。它同时解决了三个问题：误操作可回退、花费有预览、冲突（超重/断路/功率不足）有地方说清楚。**注意两个细节**：①拖动期间不要重算总战力，用 `lastDraftChange` 空闲 1.2s 再算（`ui.js:448-453`）；②确认按钮禁用时必须把 `reason` 放进 `data-tip`（`ui.js:938`），否则玩家不知道为什么点不动。

**5. 画布上"点车厢挂点"要抄 `Follow.pick`，不要抄 `pickStation`。**
挂点随列车移动，必须用"渲染时写回屏幕坐标 + 帧号"的缓存（`follow.js:77-86`：`tr.sx/tr.sy` + `R.frame - tr.drawn > 1` 过滤过期帧）；`pickStation`（`render.js:3142-3151`）是静态目标，缓存一次就够，照抄会点到"上一帧的挂点"。三个具体参数直接沿用：命中半径 = 图标半径 + 7px、候选排序取最近、触屏不显示悬停提示（`tools.js:122`）。再加一条原作没有的：**挂点被遮挡（车厢侧视角）时必须回退到"车厢级"点击**，否则玩家点不到另一侧的挂点——这才是新游戏真正的交互难点，不是坐标系。
