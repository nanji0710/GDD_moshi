### 1.3 ⚠ 未被声明的第三方数据源：`data_china.js` / DataV

本次分析发现的**许可缺口**，原项目文档未披露：

- `tools/pipeline/build-atlas.mjs:3`：「输入：`tools/src/china_provinces.json`（**阿里 DataV 省级 GeoJSON**）」

## 2. 地理数据格式：一城是怎么定义的

### 2.1 文件骨架

`js/geo_gz.js:1-6`（基底五图用 `CM.GEO`，54 城用 `CM.MAP_GEO[id]`，见 `fetch-geo.mjs:739-742`）：

```js
'use strict';
// 由 OpenStreetMap 数据生成（© OpenStreetMap 贡献者，ODbL）。坐标为游戏格（250 m），折线为增量编码，1/64 格精度。
(function (CM) {
  CM.GEO = {
    proj: { lon0: 113.2, lat0: 23.215, kx: 409.6, ky: 443 },
    water: [...], roads: [...], streets: '...!...!...', rail: [...],
    parks: [...], reserves: [...], woods: [...], admin: [...], places: [...],
    names: ['', '三枝香水道', ...],   // 0 号必须是空串
  };
})(window.CM);
```

投影是**局部等距矩形近似**：`x = (lon-lon0)*kx`，`y = (lat0-lat)*ky`，左上原点、x 东 y 南（`js/data_gz.js:2`）；`kx/ky` 由「每度经纬度对应多少格」反算（`fetch-geo.mjs:518-521`）。

### 2.2 编码

`js/geo.js:9-22` 的 `dec()`：每 5 bit 一个字符（`+63`），低 1 位符号位，坐标先 `×64` 取整再折线内差分；`js/geo.js:37-42` 的 `enc()` 是逆过程（虚构地图教程用它写同样格式）。精度 1/64 格：`cellM=250` 时约 3.9 m，`cellM=1040` 时约 16 m（`fetch-geo.mjs:24-25`）。多边形用 `'o'`/`'i'` 前缀区分外环/内环（`js/geo.js:32`），支路 `streets` 是一个大字符串、用 `!` 分隔（`js/geo.js:58`）。

### 2.3 图层与字段

| 图层 | 行结构 | 说明 | 证据 |
|---|---|---|---|
| `water` | `[nameIdx, widthCells, 'enc']` 或 `[nameIdx, 'o'+enc, 'i'+enc…]` | 线状（河/渠）按宽度画，面状（湖/海）用环 | `js/geo.js:53-56` |
| `roads` | `[nameIdx, cls(2/3/4), flags, 'enc']` | flags：`1`桥 `2`隧道 `4`匝道 `8`单向 | `geo_gz.js:2069`、`js/geo.js:57` |
| `streets` | `'enc!enc!…'` | 无名支路，只画不参与拓扑 | `js/geo.js:58` |
| `rail` | `[nameIdx, flags(1桥 2隧道 16高速), 'enc', year?]` | **新游戏的轨道素材就在这一层** | `geo_gz.js:21847`、`js/geo.js:59` |
| `parks`/`reserves`/`woods` | `[nameIdx, 'o'+enc, …]` | 公园/休闲地/林地 | `js/geo.js:60-62` |
| `admin` | `[level(6 区 / 8 街道), nameIdx, 'o'+enc…]` | 行政区界，`build-data.mjs` 靠它切 region | `geo_gz.js:23078` |
| `places` | `[name, x, y, level]`（已解码为格坐标） | level：`0`地铁站 `1`火车站 `2`街区 `3`村 `4`岛 | `geo_gz.js:23211`、`fetch-geo.mjs:613` |
| `names` | `['', '名字', …]` | 全文件名称表，所有 `nameIdx` 指向它 | `js/geo.js:48` |

### 2.5 ⚠ 两个必须知道的坑

**坑 1：`GEO.cellM` 与 `CFG.CELL_M` 是双轨制，引擎只认后者。** `fetch-geo.mjs:718` 把每城格距写进 `GEO.cellM`（250～1040 m 不等），但 `js/config.js:12` 全局写死 `CELL_M: 250`，而 `js/maps.js:7` 的 `CFG_KEYS` 里**没有 `CELL_M`**，全仓库也没有第二处给 `CELL_M` 赋值。后果：北京 870 m/格、广州 1040 m/格的图在引擎里一律按 250 m/格解释——**物理距离被压缩 3～4 倍、密度被放大约 12 倍**。启示很直接：**「一格多少米」必须是一等公民**，跟着地图一起切换，否则未来做「列车 60 km/h 推进」时算不出正确的视觉速度。

**坑 2：道路等级只画 2/3/4，其它等级静默丢弃。** `js/render.js:702` 是 `const lay = { 2: [], 3: [], 4: [] }`，之后直接 `lay[gr.cls].push(w)`，`cls` 为 5/6/7 时不报错也不画。所以 `fetch-geo.mjs` 必须把 OSM 七档折叠成三档（`fetch-geo.mjs:76-99` 的注释给了真实直方图 `{2:6014, 3:8771, 4:4988}`）。同一坑记录在 `docs/独有玩法与数据管线.md:962-964`。

### 2.6 这套格式直接做「被丧尸占领的城市地图」合适吗

**结论：骨架可用，图层要换，字段要加。**

| 维度 | 判断 | 说明 |
|---|---|---|
| 投影 + 增量编码 + 名称表 | ✅ 直接可用 | 与领域无关的纯几何压缩；一张废土图 100 KB～1 MB |
| 道路层 | ✅ 可用（街道网） | 丧尸寻路/刷怪点分布直接用 `roads`/`streets` 折线 |
| **铁路层** | ✅ **最重要**，但要扩 | 现有 `rail` 只有桥/隧道/高速三 flag，没有**侧线/废弃状态/站场**；新游戏要换轨、要侧线，需加 `kind`(main/siding/wreck)、`service`(active/abandoned)（`year` 已有，`js/geo.js:59`） |
| 水系/公园/林地 | ✅ 可用（障碍与视觉） | 废土视觉靠调色板，不靠数据 |
| 行政区界 | 🔸 语义下降 | 可改用途：尸潮分区 / 污染浓度分区 |
| 建筑 | ❌ **没有这一层** | 底座只画「程序化城市街块」，无 OSM 建筑轮廓；要「破败楼房当掩体」必须**新增 `buildings`**（含 `h` 高度、`damage` 损毁度） |

### 3.2 `fetch-geo.mjs`（34.5 KB / 851 行，最关键）

头部把格式契约定死（`:12-25`）：与 `geo_gz.js` 的格式约定「必须逐位一致」，因为解码器是 `js/geo.js` 的 `Geo.dec`；且**直接产出引擎格式、不落中间 JSON**（`:8-10`：「中间多一层格式只会多一个『两边不一致』的机会」）。抓取方式是 **Overpass API，不是 PBF**（`:56-64`）。七个值得抄的工程决策：

| # | 决策 | 为什么（原文要点） | 证据 |
|---|---|---|---|
| 1 | 镜像池按实测可用性排序，且**校验真的返回了数据** | `overpass.osm.ch` 对中国查询返回 `200 + {"elements":[]}`，曾被置顶，整轮产出空地图 | `:40-64`、`:351-381` |
| 2 | 429/504 是**限流**不是端点坏了：等 15→40→90 s，优先重试同一端点 | 四镜像轮流被打会全进冷却，整城失败 | `:279-300` |
| 3 | 端点健康表 + 分级冷却（连不上 20 min，5xx/超时 5 min） | 坏镜像不能让每块都去撞一遍 | `:291-315` |
| 4 | **分块抓取**（45 km/块，最多 3×3，重叠 6%） | 一次大 bbox 会 300 s 超时；某块失败只重试那块 | `:387-464` |
| 5 | **块级磁盘缓存** | 公网镜像高负载时跑不完 53 城，不落盘就永远从头开始 | `:36`、`:395-399` |
| 6 | 小城优先 | 北京中心块单块十几分钟，堵死 worker 后 44 个小城一个都发不出去 | `:792-807` |
| 7 | 默认单并发，`--jobs` 才放开 | 实测 3 并发 → 四镜像两分钟内全 429/502/504，随后 IP 级限流 | `:808-825` |

处理链（`:562-750`）：`cityBBox` → `gridOf` → `makeProjector` → 遍历 `elements` 按 tag 分流到 7 图层 → 顶点超限再抽稀 → `enc()` → 写 `CM.MAP_GEO[id]`。成本常量：`MAX_SIDE=128`、`PAD=1.18`、`SIMPLIFY_M=22`、`MAX_POINTS=42000`（`:67-74`），以及 `maxRoadClassFor(cellM)`「格越粗只要越主干，但永不砍到只剩快速路」（`:218-241`，注释记了一次真实回退：砍到 2 档后南京/杭州/广州/青岛/郑州/成都 `cls3=0 cls4=0`）。

## 6. 音频：100% 代码合成

### 6.1 证据：仓库里没有任何音频文件

全仓扫描 `*.mp3/*.ogg/*.wav/*.m4a/*.aac/*.flac`（排除 headless 浏览器 profile 目录）= **0 个**；字体 `*.ttf/*.woff*` 也是 0；`img/` 只有 7 张 PNG（favicon + 2 logo + 4 宣传图）。代码写得很直白：`js/sound.js:2`「音效：Web Audio 实时合成（**无外部音频文件**）」；`js/soundscape.js:2`「动态城市与地铁声音（v2.0）：**全部用 Web Audio 实时合成，没有音频文件**」。

### 6.2 混音拓扑（`js/sound.js:13-35`）

```
                 ┌→ sfxBus ─────────────────────────┐
tone/bell/noise ─┤                                  │
                 ├→ trainBus (gain=trainVol) ───────┤
                 │                                  ▼
                 ├→ ambBus(gain=ambVol) → ambFilter(lowpass 18000Hz)
                 │                                  │
                 └──► master(gain=vol*0.9) → DynamicsCompressor(-16dB, ratio 4) → destination
```

三条总线分开调（界面/列车/环境），环境总线带低通（地下视图变闷：`js/sound.js:201`、`js/soundscape.js:203`）；噪声不是采样，是**启动时生成的 2 秒白噪 buffer**（`js/sound.js:28-30`），所有噪声源共用并随机起点；解锁靠 `pointerdown` + `keydown` 捕获阶段（`:36-37`），`visibilitychange` 时 `suspend`/`resume`（`:39-45`）；声像只有 `StereoPanner`（`:47-51`），无 3D Panner / HRTF。

### 6.3 三个合成原语（核心资产）

| 原语 | 签名 | 实现要点 | 证据 |
|---|---|---|---|
| `tone()` | `(f, dur, type, gain, delay, f2, attack, dest)` | 振荡器 + 增益包络；`f2` 用 `exponentialRampToValueAtTime` 滑音；起音默认 6 ms | `js/sound.js:71-84` |
| `bell()` | `(f, dur, gain, delay, dest)` | 基频 + `2.01f` + `3.02f` 三个正弦泛音（非整数倍避免金属感过强） | `:86-90` |
| `noise()` | `(dur, type, freq, q, gain, delay, freq2, dest)` | bufferSource(loop) → biquad(bandpass/lowpass/highpass) → 增益包络；`freq2` 扫频 | `:92-105` |

调度**全部基于 `ac.currentTime + delay` 的 `setValueAtTime`/`exponentialRampToValueAtTime`**，不用 `setTimeout`，不会因主线程卡顿错拍。每个源挂 `onended` 主动断链（`watchSource`，`:60-68`），避免长时间点击累积无输入的 gain/filter 节点——这是 WebAudio 最常见的内存泄漏，这里处理掉了。

### 6.4 音效表

界面音效 `SFX` **21 个**（`:107-139`）：`click/soft/open/close/tool/place/lay/demolish/build/good/error/notify/fanfare/unlock/month/whoosh/swoosh/chime/pause/play/toggle/fail/coin/celebrate`。动态短音 `CUE` **10 个**（`:142-156`）：`doorOpen/doorClose/brake/depart/bird/insect/horn/ship/bikeBell`。去重：同名 45 ms 内不重复，`click` 全局 25 ms 节流（`:165-167`）。

### 6.5 声音场景 `soundscape.js`（15.2 KB / 229 行）

架构是**固定声部 + 平滑参数**，绝不逐帧创建节点（`:2-6`）：

- **5 个环境层**（`:51-55`）：车流 `lowpass 420Hz` / 城市远景 `bandpass 150Hz` / 商业人声 `bandpass 1150Hz` / 水面 `lowpass 480Hz` / 树叶 `bandpass 3400Hz`；每层是 `噪声 → 滤波 → (可选 LFO 调制) → 增益 → 声像 → 环境总线`（`:21-34`）
- **3 个列车声部**（`CFG.perf.trainVoices`，`:36-48`）：滚动噪声(lowpass) + 电机锯齿波(90Hz) + 轮轨节拍（方波调制 gain）→ 隧道闷声 lowpass → 增益 → 声像
- 驱动频率：`tick(dt)` 每 **0.12 s**（`:181-182`），视野采样每 **0.5 s**（`:192`）
- 视野采样 `sample()`（`:63-94`）：视野内 9×7 网格统计 urban/com/water/green 占比与左右位置（→ 声像），叠交通量与拥堵
- 列车声音分配（`:108-154`）：按 `响度 =(0.12+0.88*min(1,sp/18))*exp(-d*2.4)*prox` 排序取前 3，**同一列车保持同一声部**（`:137`）避免音色跳变
- 状态机短音（`:121-131`）：比较上一帧/这一帧的 `state/door/until`，触发 `brake`/`doorOpen`/`doorClose`/`depart`
- 偶发短音（`:217-225`）：鸟/虫/喇叭/自行车铃/船笛，按「每秒概率 × 环境占比 × 近景程度」触发，同时最多 `CFG.perf.maxOneShots`（默认 6）个（`:96-105`）
- 诊断接口 `levels()`（`:168-174`）返回各声部目标音量——**声音系统可被自动化断言，这点很值得抄**

**改造难点（诚实评估）**：① **并发声部上限**——`maxOneShots` 默认 6（`soundscape.js:99`），对「四把枪 + 20 只丧尸」远远不够，要么提到 24–32，要么做音效聚合（同帧同类枪声合成一个「齐射」）。这是最大改造点。② **距离衰减没有内建**——现在响度是手算 `set(gain, loud)`（`:117`），枪战要每帧重算几十个源，建议把「声源对象池 + 每 100 ms 更新参数」做成独立模块。③ **没有采样音源**——全是合成；想用真实枪声要新增 `sample→bufferSource` 原语，但会破坏「零资源」优势（一个枪声库 2–5 MB）。④ **没有 HRTF**——`StereoPanner` 只有左右，等轴视角可接受，但「背后有丧尸」的方位感弱。

### 7.3 懒加载：抄思路，不抄机制

`js/maps.js:123-147` 的 `CM.loadGeo(id)`：已完成直接返回、并发复用同一 Promise、失败可重试、成功后缓存。优点齐全，缺点是**用 `<script>` 注入而不是 `fetch`**——等于把数据当代码执行（CSP 不友好、无法取消、无法在 Worker 解析）。新游戏应 `fetch('data/maps/x.json')` → `JSON.parse`（或 `ArrayBuffer` + 自写解码）+ `AbortController`，可放进 Web Worker。

### 7.4 新游戏的工程建议

**结论：原生 ESM + 不打包（V1）；需要单文件分发时再上 esbuild。**

1. 浏览器原生 `import` 已够；HTTP/2 下 50 个模块的加载开销在本地 ≈ 几十 ms，**dev 阶段完全不需要构建**
2. 保留「`node` 直接 import 同一个模块」的能力 → `simcheck` 这类 headless 测试**零成本**（这是本项目最大的工程遗产，用 ESM 比 IIFE 更自然）
3. 数据不要写成 `.js`：用 `data/*.json` + `fetch`。既避免 2 MB AST 解析，也避免「数据文件里出现游戏代码」
4. 打包时机：① 上架 itch/Steam（Electron/Tauri 要单目录）② 想要单文件 HTML ③ 模块数 >150。届时 `esbuild --bundle --format=esm` 一行命令，`node tools/` 脚本不受影响
5. **不要引入框架**（React/Vue）：Canvas 主循环 + 少量 DOM 面板，框架只增加 GC 与心智负担；用「模板字符串 + 事件委托 + 增量更新」就够

**可测性纪律（抄这个比抄代码重要）**：`src/core/**` 禁止 import 任何 DOM/Canvas 模块（用 import 白名单脚本卡住）；核心只暴露纯函数/纯类，`main.js` 只做装配；`tools/simcheck.mjs` 直接 `import '../src/core/xxx.js'` 断言数值；渲染/音频/UI 通过注入的接口被核心调用（依赖倒置），headless 时传空实现。

### 9.2 ESM / 打包器决策

| 阶段 | 决策 | 理由 |
|---|---|---|
| V1（现在） | **原生 ESM，不打包** | 零依赖、dev 零构建、`node` 与浏览器共用同一份 core |
| V1.5 | 加 `tools/lint-imports.mjs`（30 行）检查 `src/core/**` 无 DOM import | 保住 headless 可测性 |
| V2（要多平台/单文件） | `esbuild` 一条命令出单文件 | 那时再加，不提前上 |

`package.json` 只要 scripts（无 dependencies）：

```json
{ "type": "module",
  "scripts": { "dev": "node tools/serve.mjs 4180", "check": "node tools/simcheck.mjs",
               "shots": "node tools/shoot.mjs all", "build": "node scripts/build.mjs" } }
```

### 9.3 地图数据怎么组织

四条硬规矩（都是从第 2/3/6 节的坑反推出来的）：① **一格多少米是一等公民**——`data/maps/<id>.json` 带 `cellM`，运行时写进全局 `CELL_M`（别重复「geo 里写 870、引擎用 250」的双轨制，见 2.5）；② **一张图一个文件、可单独替换**（200–500 KB，按章节再切分增量加载），不要 2 MB 聚合文件；③ **数据与数值分离**（`data/maps/` vs `data/balance/`），改数值不用重跑地理管线；④ **每个数据文件带来源字段**：

```json
{ "v": 1, "id": "wasteland-01", "cellM": 8, "size": [512, 256],
  "source": "© OpenStreetMap contributors, ODbL 1.0",
  "layers": { "water": [], "roads": [], "rail": [], "buildings": [], "props": [], "zones": [] } }
```

**尺寸预算**：一张废土图（512×256 格 × 8 m = 4×2 km）含铁路 + 建筑 + 道具，编码后 **150–400 KB**、gzip 后 **40–90 KB**；首屏只需 1 张，比本项目 1.4 MB/城轻一个数量级。**轨道层是主数据**：`rail` 存 `kind`(main/siding/wreck) 与 `service`(active/abandoned)，并**预计算弧长 `cum` 写进数据文件**——省掉运行时一遍遍历，让「车头在第几米」变成 O(1)。

## 10. 给主设计师的 5 条结论

1. **先定商业模式，再定代码策略。** 底座是「非商业使用许可证 1.0」，`LICENSE.txt:19-27` 明文禁止一切商业使用，并**专门堵了「仅使用部分代码」这条退路**（`:27`）。非商业 → 整套代码 + 管线 + 音频都能搬（保留许可/署名/标明修改）；商业 → 一行代码都不能抄。**但地图数据是另一条权利线**：`geo_*.js` 是 ODbL 1.0 数据，**允许商用**，只要署名 + 衍生数据库同样以 ODbL 开放 + 保持可下载（`LICENSE.txt:34-40`、ODbL 4.2/4.3/4.4/4.6）。推荐先走「非商业快速验证 + 代码结构自己写」的混合路线，把将来换壳成本压到最低。

2. **只抄「骨架」，不抄「内容」。** 本项目真正稀缺的是三样：`CM.GEO` 的图层/编码格式（`js/geo.js:46-70`、`js/geo_gz.js:4-6`）、Overpass → 分块缓存 → 编码 → 懒加载这条管线（`tools/pipeline/fetch-geo.mjs`）、以及 `scripts/build.mjs` + Cloudflare Pages 这套零依赖发布方式。要扔的是：54 城真实城市选型、POI→人口/就业整套推导（`build-data.mjs:272-367`）、DataV 省界数据（`build-atlas.mjs:3`，**来源许可在原仓库里悬空，别碰**）。

3. **可测性是这个项目最值钱的工程资产，必须继承。** `simcheck.mjs` 能在 Node 里跑完整仿真并跑 91 项断言，前提是**仿真核心零 DOM 依赖**（`simcheck.mjs:15-66` 的 `ORDER` 里没有 render/ui/agents）。新游戏从第一天就要把 `src/core/**` 隔离成「可在 node 里 import 的纯逻辑」，否则等你有一百只丧尸和四把枪时，任何数值 bug 都只能靠肉眼。

4. **音频零资源是最大的意外之喜，2–4 人日就能做出枪战音效。** 仓库里 0 个音频文件，全部 WebAudio 实时合成（`js/sound.js:2`、`js/soundscape.js:2`）；三原语（`js/sound.js:71-105`）+ 三总线拓扑（`:13-35`）足够做枪声、霰弹、机枪、爆炸（含尾音与碎片）、丧尸嚎叫（锯齿 + LFO 颤音 + 气声噪声）。真正要改的是**并发声部**（现默认 6，`soundscape.js:99`）与**距离衰减**，不是合成能力。

5. **不要继承这四条技术债。** ① 手写 `index.html` 顺序（`index.html:28-82`）→ 用 ESM；② 2 MB 的 JS 数据文件（`js/geo_guangzhou.js`）→ `fetch` + JSON/二进制；③ `GEO.cellM` 与 `CFG.CELL_M` 双轨制（`fetch-geo.mjs:718` vs `config.js:12`，`maps.js:7` 不切 `CELL_M`）→ 一格多少米必须跟着地图一起切；④ 单文件巨型模块（`render.js` 209 KB / `ui.js` 153 KB / `pages.js` 136 KB）→ 按领域拆 20–40 个模块。这四条都是「只有一个开发者 + 只有一张图」时的合理妥协，在你的项目里会直接变成事故。
