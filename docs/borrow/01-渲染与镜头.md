## 1. 坐标系与投影（一切的地基）

### 1.1 世界坐标 = 网格坐标，不是米

`config.js:12` → `W: 120, H: 96, CELL_M: 250, ZONE: 4`

- 世界是一张 **120 × 96 格子图**，1 格 = **250 m**，全图 **30 km × 24 km**。
- **世界坐标单位 = 格**（不是米）。`cam.cx=30, cam.cy=40`（`render.js:76`）表示对准第 30 列第 40 行；世界范围恒为 `[0,120]×[0,96]`。
- 米→世界单位只在需要时换算：`EX = 2.0 / CFG.CELL_M`（`render.js:7`）= 0.008，注释写着「米 → 世界单位（**夸张**）」。

**硬约束**：30 km 内一格 250 m 对「一列车慢慢推进」太粗（丧尸只是格内一个点）。新游戏应把世界单位定为 1 m（`CELL_M` 降到 8–20 m，`W/H` 提到 400×300 级），但**投影函数 `P()` 一行不用改**——它只关心世界单位，不关心一单位多长。

### 1.2 投影 P(x, y, h)：2.5D 的全部秘密

`render.js:355-361`：

```js
Renderer.prototype.P = function (x, y, h, out) {
  const M = this.M, z = this.z; out = out || {};
  out.x = this.ox + (M[0] * x + M[1] * y) * z;
  out.y = this.oy + (M[2] * x + M[3] * y) * z - (h || 0) * this.hs;   // ← 高度只影响 y
  return out;
};
```

`M` 是 2×2 投影矩阵，`hs` 是「每世界单位高度对应多少屏幕像素」，都出自 `computeTransform`（`render.js:345-354`）：

```js
const t = U.easeInOut(c.t);                                   // 0 = 俯视 2D, 1 = 等距 2.5D
const m00 = U.lerp(1, ISO[0], t), m01 = U.lerp(0, ISO[1], t),
      m10 = U.lerp(0, ISO[2], t), m11 = U.lerp(1, ISO[3], t);
this.M = [m00, m01, m10, m11]; this.z = c.zoom;
this.det = m00 * m11 - m01 * m10;                             // 行列式，unproject 用
this.ox  = this.w / 2 - (m00 * c.cx + m01 * c.cy) * c.zoom;   // 相机中心→屏幕中心
this.oy  = this.h / 2 - (m10 * c.cx + m11 * c.cy) * c.zoom;
this.hs  = c.zoom * HSF * t;                                  // 高度屏幕系数
this.tEase = t;
```

`ISO = [0.70710678, -0.70710678, 0.35355339, 0.35355339]`（`render.js:5`）：

```
screenX = 0.707·x − 0.707·y
screenY = 0.354·x + 0.354·y − h·hs
```

纵向系数 0.354 恰为 0.707 的一半 → **经典 2:1 斜二测（dimetric），不是 30° 真等距**（真等距是 `[0.866,-0.866,0.5,0.5]`）。2:1 更适合「格」为基础的地图：对角线刚好 2:1，格边不出现非整数像素。

### 1.3 立体感的真实强度：1.64×

| 量 | 值 | 出处 |
|---|---|---|
| 水平像素/米（z=13） | `z / CELL_M` = 0.052 px/m | — |
| 垂直像素/米 | `EX·HSF·z` = 0.008×0.82×13 = 0.0853 px/m | `render.js:7, 6, 352` |
| **垂直夸张倍数** | `EX·CELL_M·HSF` = **1.64×** | 推导 |

**「2.5D 立体感」= 2:1 斜投影 × 1.64 倍垂直夸张。** 想要更「立」的废土，把 `EX` 从 `2.0/CELL_M` 改成 `3.0/CELL_M` → 2.46×，列车与废墟立刻拔高。**常量级改动。**

### 1.4 逆变换、点选与「高度平面拾取」

`unproject(sx,sy)`（`render.js:362`）返回 **h=0 地面平面**交点；`screenToWorldDelta`（`366`）只做位移逆变换。现有代码**没有**「按高度反解」能力，但一行能加——新游戏点选车顶炮塔必需：

```js
Renderer.prototype.pickOnPlane = function (sx, sy, h) {
  const M = this.M, a = (sx - this.ox) / this.z, b = (sy + h * this.hs - this.oy) / this.z;
  return { x: (M[3]*a - M[1]*b) / this.det, y: (-M[2]*a + M[0]*b) / this.det };
};
```

### 1.5 2D ↔ 2.5D 是连续插值，不是开关

`cam.t`（当前）/`cam.tu`（目标）成对存在，`updateCamera` 以 `dt/0.5` 线性逼近（`render.js:411-412`），再经 `U.easeInOut` 三次缓动（`util.js:10`）。**所有绘制只认 `tEase` 一个数**（`render.js:353`），不存在两套分支 → 新游戏做「平时俯视、开火时压低角度」等于零成本。`under`（地下视图 0→1，0.35 s，`render.js:413`）是同一机制：`UNDER_DEPTH=4`（`render.js:12`）把 `h<0` 轨道再压 4 倍，地面降到 32% 不透明（`render.js:1770` 的 `1-0.68*under`）。做「穿隧道/地下站」可直接复用。

## 2. 渲染管线结构

### 2.1 主循环（`main.js:239-261`）

```
rAF frame(t)
 ├ dt = min(0.1, (t−last)/1000)                    main.js:241   ← 唯一时间钳制
 ├ g.update(dt) / CM.agents.update(dt,g,R)          main.js:245-246
 ├ CM.Follow.tick(dt)                               main.js:247   ← 镜头（改 cx/cy）
 ├ R.render(dt, ui)                                 main.js:254   ← 只画
 └ R.noteFrameTime(performance.now() − workStarted)  main.js:257
```

**没有固定步长、没有累加器**：`dt` 直接喂给所有系统，只做 0.1 s 上限。→ 对丧尸游戏是**明确反例**（144 Hz 与 30 Hz 下子弹碰撞/追击行为不同）。

### 2.2 `render()` 的绘制顺序（`render.js:1747-1943`）

| 行号 | 做什么 |

| 1759-1766 | 全屏底色 `mixc(fog,bgUnder,under)`；4 角 unproject 算 `this.view`（底边多留 `MAX_H·hs`） |

| 1775-1778 | `eff = z·min(dpr,1.5)·(1−0.28t)·detailScale` → `rasterLevel()` 选 LOD |

**关键洞察（务必抄）**——第 7 行把静态建筑与动态实体**交错**绘制，遍历序为 `i+j` 对角线：

```js
render.js:1847  list.sort(function (a, b) { return (a[0]+a[1]) - (b[0]+b[1]) || a[0]-b[0]; });
render.js:1859  if (buckets) { const bk = buckets.get(ci + ':' + cj); if (bk) agents.drawList(ctx, this, bk, agentAlpha); }
```

→ **实体获得了免费的、与建筑正确的遮挡关系**（画家算法），不需要 z-buffer，也不需要逐物体排序。「丧尸从楼后走出」这类核心视觉直接白拿。

### 2.3 resize / DPR（`render.js:335-342`）

```js
const dpr = Math.min(2, window.devicePixelRatio || 1);
if (w === this.w && h === this.h && dpr === this.dpr) return;       // 短路
this.cv.width = Math.round(w*dpr); this.cv.height = Math.round(h*dpr);
this.cv.style.width = w+'px'; this.cv.style.height = h+'px';
```

DPR 上限 **2**（4K 屏不炸显存）；只在真变化时改 `width/height`（赋值会清空画布并重新分配）。**缺陷**：没监听 `devicePixelRatio` 变化（浏览器缩放/外接屏会糊）。CSS 侧 `css/style.css:70`：`#map { position: fixed; inset: 0; touch-action: none; }`（移动端拖拽必备）。

### 2.4 主题：两张巨型配色表 + 全缓存重建

`render.js:15-70` 定义 `THEMES.light` / `.dark`，各约 55 行、200+ 令牌：`bg/bgUnder/fog/cloud`、`ground.*`、`pal[1..6]`（建筑色板，hash 挑近似色）、`road.{local,coll,art,exp,rail}{,Case,Line}`、`trk.{tunnelWater,ballast,sleeper,deck,parapet,wall,pierFoot,shadow}`（v2.0 轨道工程）、`isoShadow/bldStroke/peak/tree/lm2d/ink/halo/district`。

`setTheme`（`render.js:328-334`）：换 `TH/GROUND/PAL` 三个模块级变量 → `clearImages()` 清空**所有** chunk → 重画总览图。

→ **末日废土直接可用**：加 `THEMES.wasteland`（土黄底、锈色道路、暗红天光）与 `THEMES.night_raid`（暗紫高对比），`drawGround`/`isoBox`/`drawTrack` 一行不改。这是全项目性价比最高的一处。注意 `TH` 是模块级 `let`（`render.js:71`），而 `drawFx` 又读 `this.th`（`render.js:279`），两套引用并存易不同步。

### 2.5 缓存：三套独立体系

**(a) 地面 chunk** — `Map<lvl:ci:cj, {cv, lvl, key, used, px, stale}>`

| 参数 | 值 | 出处 |
|---|---|---|
| `CHUNK_PX` / `LEVELS` | 512 / `[8,16,32,64]` | `render.js:9` / `render.js:8` |
| 每级 chunk 世界尺寸 | `512/lvl` = 64/32/16/8 格 | `render.js:823` |
| 单块像素 | 514×514（+2 防接缝） | `render.js:824` |
| `cacheMaxPx` / `chunkBudgetMs` | **24e6**（≈91 块）/ **6 ms** | `config.js:216` |

绘制方式（`render.js:822-828`）——**精髓**：

```js
const cv = makeCanvas(CHUNK_PX+2, CHUNK_PX+2), ctx = cv.getContext('2d');
ctx.setTransform(lvl, 0, 0, lvl, -x0*lvl+1, -y0*lvl+1);   // ← 直接用世界坐标画！
this.drawGround(ctx, x0-1/lvl, y0-1/lvl, x0+C+1/lvl, y0+C+1/lvl, lvl);
```

`drawGround`（`render.js:547-760`，214 行）**完全不知道自己在画 chunk**——它拿世界坐标直接画，靠 `setTransform` 缩放。所以同一份函数既能画 chunk，也能画总览图（`838-846`：`setTransform(4,...)` + 逐行 `clip`）。**新游戏一定要抄这个「世界坐标直画 + transform 缩放」的分层方式**，它让 LOD 退化成纯 transform 参数。

**(b) 等距建筑 chunk** — 单独一套 `Map<i+lvl:ci:cj, {cv, ax, ay, px, used, born}>`：建筑有高度会**越出所在格**（`isoChunkGen` 的 `pad = hasHill ? 2.8s : 4`，`render.js:868`），尺寸按等距外接框算（`849-852`：`C = 512/lvl/√2`）。两个值得抄的点：

1. **生成器分帧**（`render.js:857-894`）——按 `i+j` 对角线 `yield`：`if (sum > i0+j0) yield progress;` 每让出一条对角线交还控制权；`render()` 用 `deadline = now + max(0.25, min(2, budget−elapsed))` 循环 `gen.next()`（`1926-1935`），**一个 chunk 可跨十几帧画完，永不掉帧**。上千丧尸的刷怪/AI 可同样切分。
2. **原子换挡**（`render.js:139-188`）：新档全部可见块画好、`ready` 才整体替换 `displayedLevel`（`182-185`）；否则继续用旧档 + 更粗块 fallback（`1794-1815`），并用 `clip()` 限制粗块不能盖住清晰邻块（`1812`）。带迟滞防抖（`144-147`：`need<=prev*1.12` 不降、`need>=prev/2*0.88` 不升）。

**(c) 淘汰 = 纯 LRU**（`render.js:452-465`）：按 `e.used` 升序丢到 `cacheMaxPx*0.8` 为止，**跳过本帧用过的**；`cachePx` 手工加减（插入 `+px`、替换 `-old.px`），不遍历求和。其它一次性缓存：`_atmo` 雾层（键含 `W×H:theme:t`，t 量化到 0.1，`205-224`）、`overview`（`829-846`）、`heat`（`1644-1746`）、拥堵位图（`2450-2482`）、`textWidths`（2048 上限后全清，`113-122`）、`geoPaths` 的 `Path2D` WeakMap（`123-127`）、`segScreens` 屏幕折线（**每帧一次** memo，`1975-1994`）。

### 2.6 自适应降档 `adaptDetail`（`render.js:101-112`）

```js
const cost = min(100, max(lastFrameMs, dt>1/45 ? dt*1000 : 0, cachePx > cacheMaxPx ? 20 : 0));
d.ema += (cost - d.ema) * 0.12;                       // EMA
d.busy = d.ema > 18 ? d.busy + elapsed : max(0, d.busy - elapsed*2);
d.calm = d.ema < 12 ? d.calm + elapsed : 0;
if (d.busy > 0.35 && d.tier < 2) { d.tier++; }        // 掉档快：0.35 s
if (d.calm > 1.1  && d.tier > 0) { d.tier--; }        // 恢复慢：1.1 s
```

三个可抄细节：① `cost` 把「实测帧时 / 掉帧惩罚 / 缓存超预算」压成一个标量；② **降快升慢**天然防抖，不需额外窗口；③ 只有 3 档，档位影响一组**离散开关**：`detailScale` 1/0.85/0.68（`render.js:1774`）、chunk 预算 `min(6, tier?3:6,…)`（`1910`）、行人上限 ×1/0.7/0.4（`agents.js:635`）、乘客预算 ×1/0.5（`agents.js:255`）、近景细节 z≥24 且 `tier<2` 才画（`render.js:2249`）、车窗/车门/乘客 `tier<2` 才画（`agents.js:254`）。

→ 新游戏把「行人上限」换成「丧尸同屏上限 + 血条 + 阴影开关」，**整个函数一字不改地搬**。

## 3. 相机系统与镜头跟随

### 3.1 `cam` 全字段（`render.js:76`）

```js
this.cam = { cx: 30, cy: 40, zoom: 13, tz: 13, anchor: null, view: 0, t: 0, under: 0, tu: 0, fly: null };
```

`cx,cy` 相机中心（世界坐标=格）；`zoom`/`tz` 当前/**目标**缩放（`zoom` 指数逼近 `tz`）；`anchor` 缩放锚点 `{sx,sy,wx,wy}`；`view`/`t` 视图模式 目标/当前（0=2D 1=2.5D，`dt/0.5` 逼近）；`under`/`tu` 地下程度（`dt/0.35`）；`fly` `flyTo` 补间，优先级最高。**没有旋转、没有 fov**。

### 3.2 `updateCamera` 三种模式（`render.js:392-416`）

```js
if (c.fly) {                                    // ① 飞行动画 0.65 s
  f.t = min(1, f.t + dt/0.65); const e = U.easeInOut(f.t);
  c.cx = lerp(f.fx,f.tx,e); c.cy = lerp(f.fy,f.ty,e);
  c.zoom = exp(lerp(log(f.fz), log(f.tzm), e));      // ← 对数插值！
  c.tz = c.zoom; if (f.t >= 1) c.fly = null;
} else if (Math.abs(c.zoom - c.tz) > 1e-3) {    // ② 缩放平滑
  const k = 1 - Math.exp(-dt * 14);                  // ← 帧率无关指数逼近
  c.zoom = exp(lerp(log(c.zoom), log(c.tz), k));
  if (c.anchor) { /* 反算 cx/cy 使锚点世界坐标不动 */ }
}
if (c.t !== tv) { const sp = dt/0.5; ... }       // ③ 视图/地下线性逼近
this.clampCam(); this.computeTransform();
```

三个必须抄的技巧：① **缩放用 `exp(lerp(log a, log b, k))`**——人眼对缩放是感知对数的，线性插值会让「13→64」前段慢后段飞；② **`k = 1 − exp(−dt·λ)`**（缩放 λ=14，跟随 λ=7）是帧率无关一阶平滑，别用 `x += (t−x)*0.1`（后者在 144 Hz 下快 2.4 倍）；③ **`anchor` 补偿**（`404-409`）：先 `computeTransform()`，再用新 `M/det` 反算 `cx/cy`，保证滚轮缩放时鼠标下的点纹丝不动。

### 3.3 `follow.js` 全文解剖（148 行）

核心只有 4 行（`follow.js:139-142`）：

```js

c.fly = null; c.anchor = null;                      // 关掉其它相机驱动，避免打架
```

进入跟随（`follow.js:91-107`）：`R.follow = tr`；`c.fly = null; c.anchor = null;`；`if (!was && R.cam.tz < 30) R.cam.tz = 32;`（**一次性设目标缩放**）；`document.body.classList.add('following')`。

✅ **对的地方**：① `R.follow` 软引用被 `drawTrains` 用来**跳过视口裁剪**（`agents.js:263, 277`）和画脉动圆环（`288-292`）；② 接管协议干净——每帧置空 `c.fly`/`c.anchor`，`updateCamera` 就完全不碰 `cx/cy`，只做 `clampCam + computeTransform`，**无状态机冲突**；③ 缩放只需设一次 `tz`，`updateCamera` 的指数逼近（λ=14，约 0.3 s）自然平滑；④ `autoUnder`（`142`）进地下自动切地下视图——「镜头语言自动化」，新游戏该学。

❌ **缺的**：**无前视**（稳态滞后 `v/λ ≈ 0.17 格 ≈ 43 m`，高速时列车贴屏幕后缘）；**跟随点是列车中点**（`o.x/o.y` 来自 `trainPos`，`agents.js:193`，不是车头）；**缩放恒定无战斗反馈**；**无屏幕震动**；**无死区**（小抖动带动全屏）；只在列车 `dying` 时换目标（`132-137`），无手动锁定。

### 3.4 「跟随列车 + 战斗时轻微拉远」的具体改法

替换 `follow.js:139-142`：

```js
const c = R.cam; c.fly = null; c.anchor = null;
// ① 跟车头 + 速度前视（米/秒 → 世界单位）
const look = U.clamp(o.v * 0.55, 0, 2.2);
const tx = o.x + Math.cos(o.a) * look, ty = o.y + Math.sin(o.a) * look;
// ② 死区：目标落在屏幕中心 ±46px 内就不动相机
const sp = R.P(tx, ty, 0, {});

// ③ 两级平滑：平时 λ=7 温和，战斗 λ=10 敏捷
const k = dt > 0 ? 1 - Math.exp(-dt * (combat > 0.3 ? 10 : 7)) : 0;
if (!inDead) { c.cx += (tx - c.cx) * k; c.cy += (ty - c.cy) * k; }
// ④ 战斗拉远：只改 tz，缓动交给 updateCamera
c.tz = 34 * (1 - 0.28 * U.smooth(combat));           // 34 → 最多 24.5
```

`combat`（0→1）由战斗管理器维护：`combatT += (wantCombat ? dt : -dt)/0.8; combat = clamp(combatT,0,1);`（3 秒内有敌进入 200 m 或开火 → 目标 1）。要点：**只改 `tz`，绝不直接改 `zoom`**；**战斗时不改 `cx/cy` 目标**（拉远+推镜叠加会晕）；用 `U.smooth` 比线性舒服；想做「开火瞬间 punch-in」，把 `c.tz` 短暂乘 1.06 再回落。

### 3.5 屏幕震动：从现有结构零成本挤出

`render.js` 的**所有**绘制最终都经过 `this.ox/this.oy`（`P()`、`setWorld()`、`segScreen()`）。在 `computeTransform` 末尾（`render.js:353` 后）插入 `this.ox += shakeX; this.oy += shakeY;`（由爆炸事件写入、每帧衰减）即得全局震动，**包括缓存的 chunk 贴图**。`segScreen` 的缓存键含 `ox/oy`（`render.js:1978`），但该缓存本就是**每帧一次**的 memo（见 `1977` 注释），无额外代价。

## 5. 列车绘制（重点 a）

### 5.1 ⚠️ 先纠正一个假设

任务猜测「车厢是独立四边形/棱柱」。**实际不是。** `Agents.prototype.drawTrains`（`agents.js:245-372`）的做法是：**把车厢接缝点投影到屏幕，再用 `ctx.stroke()` 沿屏幕折线画一条粗线（`lineWidth = width`），每节车厢单独一笔、之间留缝。**

车厢**没有宽度的几何定义**——「宽度」就是 `ctx.lineWidth`（`agents.js:251`）：`const width = U.clamp(z*0.075, 2.4, 7.5);`

所以列车是「平面带状体」，立体感完全来自**高度偏移 + 侧向小刻度 + 圆角端头 + 明暗双描边**，而不是 3D 体块。对经营游戏这是对的（便宜、永不穿模），但对「丧尸爬上列车」的射击游戏不够——需要真侧立面（§5.5 给方案）。

### 5.2 多车厢沿曲线排布（可直接照抄）

**第 1 步 · 列车在弧长上的位置** — `trainPos`（`agents.js:193-199`）

```js
const f = legFrac(min(t.t, L.T), L.T, L.Lm, L.v, CFG.metro.accel);  // 区段内 时间→里程比（含加减速）
const d = L.d0 + (L.d1 - L.d0) * f;                                 // 区间起点里程 + 比例
out.d = d; out.fwd = L.d1 >= L.d0; out.k = L.k; out.rev = L.rev;
```

`d` 是沿整条线路的累计里程（世界单位）。核心是 `legFrac`：给定区段长 `Lm`、最高速 `v`、加速度 `accel`，用运动学公式算「时间→里程比」（加速—匀速—减速三段）。

> **这是梯形速度曲线的解析解，不是积分**——所以可以任意跳时间、暂停、读档后完全复现（`agents.js:214-215` 注释明说「纯函数」）。**新游戏必须抄**：把「列车在第几米」写成 `f(时间)` 的纯函数，白拿暂停/倍速/读档/跳过站/回放。丧尸不能这样做（要 AI），但列车可以。

**第 2 步 · 车身前后端** — `trainSpan`（`agents.js:202-211`）

```js
const CAR_M = 20, GAP_M = 1.6;                                       // agents.js:202

  const lo = Math.min(head,rear), hi = Math.max(head,rear);

```

**第 3 步 · 逐厢接缝点投影** — 全篇最关键的 20 行（`agents.js:265-275`）


**逐行真意**：① 车厢**不是**刚性四边形沿曲线摆放，而是**每节接缝都独立在曲线上取点**——转弯时各节自动「分别转向」、接缝自然错开，正是真实列车过弯的样子，**完全不需要旋转矩阵**；② `U.posAt(pts,cum,d,out)`（`util.js:95-114`）用**二分查找**在 `cum`（累计弧长）里定位，返回 `{x,y,a,i,f}`（`a` 切线角、`i` 折线段下标、`f` 段内比例）；③ `off = 0.055*dir` 沿**左法线** `(-sin a, cos a)` 偏移，实现上下行不重叠——**这也是「侧面挂东西」的第一个模板**（§5.4）；④ `joints[]` 来自 `this._joints` 复用数组（`agents.js:257`），每帧零新对象。

**第 4 步 · 每节车厢一笔画** — `carPath` + 双描边（`agents.js:301-315`）

```js
const gapPx = nCar > 1 ? Math.min(0.5, carGap/carLen) : 0;   // 接缝占比，上限 0.5
```

**性能要点**：所有车厢路径合并进**一个** `beginPath()`，两次 `stroke()` 搞定整列车。10 节车厢 = 2 次 stroke，不是 20 次。

**第 5 步 · 细节按缩放分级**：整列车退化为圆点 `z<7`（`293-297`）；多节车厢 `z≥14`（`267`）；车窗 `z≥22`（`320-325`）；前照灯（光晕需 `z≥18`）+ 尾灯（`327-333`）；车门 `z≥30`（`335-344`）；上下车乘客 `z≥30 && tier<2 && speed≤2`（`346-367`）。

### 5.3 车门开合：动画写成纯函数（`agents.js:217-235`）

```js
const DOOR = { delay: 2, open: 2, closeLead: 6, close: 2, walk: 3, gap: 1.1 };   // agents.js:217
```

### 5.4 「往侧面 / 上方挂东西」怎么定位（新游戏核心）

**所有挂点都从 `joints[]` 出发，两种偏移空间各有用途：**

**(A) 屏幕空间偏移** — 适合纯装饰（装甲板、贴纸、门、窗）。模板就是车门（`agents.js:339-341`）与乘客（`355-358`）：`const nx = -dy/l, ny = dx/l; const px = x + nx*d, py = y + ny*d;`。优点：恒定像素宽度，缩小时不消失，视觉稳定。缺点：**不随缩放/视角变化、无法正确遮挡**，不能用于「丧尸爬上车顶」这类需要世界位置的交互。

**(B) 世界空间偏移 + 高度投影** — 推荐，适合武器挂点。因为 `P()` 自带高度项：

```js
// 车厢 k 上、相对位置 frac(0..1)、侧向 side(-1..1)、离轨面 hMeters 的挂点
function mountWorld(rt, sp, k, frac, side, hMeters) {
  const d  = wrapD(sp.head - sp.dir * (k + frac) * (CAR_M / CFG.CELL_M), sp.total, sp.loop);
  const q  = U.posAt(rt.pts, rt.cum, d, {});
  const nx = -Math.sin(q.a), ny = Math.cos(q.a);          // 世界左法线
  const off = side * MOUNT_SIDE;                           // ≈车宽/2，世界单位
  return { x: q.x + nx*off, y: q.y + ny*off,
           h: heightAt(rt, q) + hMeters * EX,              // 米→世界单位（EX=2/250）
           a: q.a };
}
const m = mountWorld(rt, sp, k, 0.5, 0, 2.6);              // 车顶中央，离轨面 2.6 m
const p = R.P(m.x, m.y, m.h);                              // → 屏幕点，自动含 2.5D 高度
```

**炮塔转向**：炮口方向在**世界空间**算 `atan2(target.y-m.y, target.x-m.x)`，然后画一条屏幕线：

```js
const tip = R.P(m.x + Math.cos(ang)*barrelLen, m.y + Math.sin(ang)*barrelLen, m.h);
ctx.beginPath(); ctx.moveTo(p.x, p.y); ctx.lineTo(tip.x, tip.y); ctx.stroke();
```

**这条线自动带正确的透视缩短**——两端过同一个投影。这是最优美的部分：`P()` 让「世界空间算逻辑、屏幕空间画」变成零成本。**唯一约束**：`P()` 只处理绕 z 轴的高度，**不处理朝向倾斜**，炮塔仰角得手动加视觉俯仰（把 `tip.y` 再减一点）。

### 5.5 重写成真 3D 车厢（推荐方案）

给每节车厢一个**世界坐标矩形底面**，用 `prism`（`render.js:928`）：

```js
const hw = 1.4/2, hl = (CAR_M - GAP_M)/2 / CFG.CELL_M;
const q0 = U.posAt(rt.pts, rt.cum, wrapD(sp.head - sp.dir*k*carLen, sp.total, sp.loop), {});
const ux = Math.cos(q0.a), uy = Math.sin(q0.a);          // 车长方向
const nx = -uy, ny = ux;                                 // 车宽方向
// 四角 = q0 ± ux*hl ± nx*hw（左上/左下/右下/右上，顺序任意，prism 会自行判外法线）
const railH = heightAt(rt, q0);
prism(ctx, pj, rect, railH, railH + 3.2*EX, WALL_COL, ROOF_COL, {});
```

得到真正的两面侧墙（可挂武器基座、可被丧尸扒住、可显示弹孔）+ 一个顶面（炮塔底座）。**10 节 × 1 次 prism（每次 ≤2 可见面 + 1 顶面）= 30 次 `fillPts`**，完全可接受。这一步约 80 行，是「车厢改装」玩法成立的物理基础。

## 6. 特效系统 `R.fx`（重点 b）

### 6.1 数据结构与生命周期

```js
render.js:89    this.fx = [];
render.js:227   const FX_DUR = { ripple:0.9, burst:1.5, dust:1.1, trace:1.3, region:2.6 };
render.js:228   addFx(kind, x, y, o):

                  if (this.fx.length > 160) this.fx.shift();           // ← 硬上限 160
```

**单个 fx 只有 6 个字段**：`kind`（5 种：`ripple`/`burst`/`dust`/`trace`/`region`）；`x,y` **世界坐标**（故相机移动时特效跟着世界走 ✅）；`o` 任意参数包 `{color, dur, delay, pts, name, small}`；`t` 已存活秒数，**初始为负 = 延迟出场**（`-delay`，把 delay 统一进 t）；`dur` 总时长；`seed` 随机种子让粒子角度/距离各不重复。

**生命周期**（`drawFx`，`render.js:239-310`）：倒序遍历（可安全 `splice`）→ `f.t += dt` → `t >= dur` 移除 → `t < 0` 跳过 → `k = t/dur`、`e = 1-(1-k)³`（easeOutCubic）。

**三个结构性事实**：① **`t` 在 `drawFx` 里推进，不在 `update` 里** → 特效与渲染帧绑定，切标签页/掉帧时被拉长、暂停时仍继续播（**对新游戏是 bug 源**，应拆出 `updateFx(dt)`）；② 全 CPU Canvas 2D，没有 WebGL/粒子缓冲，**从未用过 `globalCompositeOperation`**；③ **绘制顺序**（`render.js:1897`）在 `drawTrains`（1893）之后、`drawAtmosphere`（1898）之前 → **所有特效永远盖在列车与丧尸上面**，做不了「地面血泊被车压住」。

### 6.2 五种现有特效的技法清单（可抄的原子）

| kind | 技法 | 行号 | 能改造成 |
|---|---|---|---|

```js
case 'text': {
  const p = this.P(f.x, f.y, 0, tmp), k2 = f.t / f.dur;
  const a = k2 < 0.15 ? k2/0.15 : (k2 > 0.7 ? (1-k2)/0.3 : 1);
  const rise = 26 * (1 - Math.pow(1-k2, 2));                  // 上浮 26px
  ctx.globalAlpha = a; ctx.textAlign = 'center'; ctx.textBaseline = 'middle';
  ctx.font = '700 ' + (f.o.size||15) + 'px ' + FONT;
  ctx.lineWidth = 4; ctx.strokeStyle = this.th.halo; ctx.fillStyle = f.o.color || '#fff';
  ctx.strokeText(f.o.text, p.x, p.y - rise); ctx.fillText(f.o.text, p.x, p.y - rise);
  break;
}
```

### 6.3 扩展成弹道/命中/爆炸/血液/飘字

**结论：数据结构完全够，改造量小，但有 4 个工程缺陷必须补。**

| 要加的效果 | 实现 | 改动 |
|---|---|---|
| 弹道（子弹飞行） | 新增 `kind:'tracer'`，`o={x0,y0,x1,y1,speed}`，按 k 插值画短亮线 + 头 | 15 行 |
| 曳光/尾迹 | **直接用现有 `trace`**，`o.pts` 传轨迹 | 0 行 |
| 命中火花 / 爆炸 | `burst` 精简版（6 粒子 + 短环，`dur:0.22`）；爆炸 = `burst` + `lighter` + 3 层不同半径/色温环 + 8 片碎片 | 10+30 行 |
| 血液 | `dust` 改色 `rgba(120,16,16,·)`，落地转持久贴花 | 10 行 |
| 飘字 / 枪口火光 | 见上 `case 'text'`；`case 'flash'` 在 `P(x,y,h)` 处 3 层径向渐变，`dur:0.06` | 15+12 行 |

**必须补的 4 个缺陷：**

1. **160 上限太小且是 FIFO**。一秒可出 200 个粒子，`shift()` 是 O(n) 且会把重要特效（爆炸）挤掉。→ **对象池 + 容量 600 + 优先级抢占**：

   ```js
   const FX = { pool: [], live: [], cap: 600 };
   function fxSpawn(kind, x, y, o, prio) {
     if (FX.live.length >= FX.cap) {
       let victim = -1, vp = 99;
       for (let i = 0; i < FX.live.length; i++) if (FX.live[i].prio < vp) { vp = FX.live[i].prio; victim = i; }
       if (victim < 0 || vp >= prio) return null;               // 挤不掉就不生成
       FX.pool.push(FX.live[victim]); FX.live.splice(victim, 1);
     }
     const f = FX.pool.pop() || {};
     f.kind = kind; f.x = x; f.y = y; f.o = o; f.t = 0; f.dur = o.dur || 1; f.prio = prio;
     FX.live.push(f); return f;
   }
   ```

2. **`t` 在 draw 里推进** → 拆成 `updateFx(dt)`（在游戏 update 里调）+ `drawFx(ctx)`（只读），暂停/跳帧/倍速才正确。
3. **无深度排序** → 至少两个通道：`fxGround`（血泊、弹坑、烟，在实体**之下**）、`fxAir`（弹道、火花、爆炸，在实体**之上**）。在 `render()` 的 `1840` 之前插一次 `drawFx(ground)`，`1897` 保留 `drawFx(air)`。
4. **无 `globalCompositeOperation`** → 加 `o.blend` 字段，在 case 内 `ctx.save()/restore()` 切 `'lighter'`，爆炸/激光才有发光感。

**额外建议**：**持久贴花**（弹孔、血泊、车辙）**不要走 fx 系统**——它们生命周期是「整局」，应画进地面 chunk 缓存（`renderGroundChunk`，`render.js:822`），再 `markDirty()` 触发重绘。1.5 秒后血泊就永久烘焙进地面，零逐帧成本。**这是这套 chunk 架构白送的礼物**。

### 7.2 空间索引：两种，用途不同

**(A) 静态网格 `Geo.buckets` / `Geo.query`（`geo.js:164-183`）— 值得直接抄**

```js
Geo.buckets = function (items, tile, W, H) {        // items 需带 bbox；tile 为桶边长（格）
  const TW = ceil(W/tile), TH = ceil(H/tile), b = new Array(TW*TH);
  for (let k = 0; k < b.length; k++) b[k] = [];
  items.forEach(function (it, idx) { /* 按 bbox 覆盖的所有桶 push(idx)，可跨桶 */ });
  return { tile, TW, TH, b };
};
Geo.query = function (bk, x0, y0, x1, y1, seen) { /* 遍历桶，Set 去重 */ };
```

用例：轨道区段（`render.js:2027-2029`）、道路（`agents.js:414`）。**只在几何变化时重建**（用版本号守门：`linkGridVer`、`roadVersion`）。→ 新游戏用来索引：**建筑碰撞盒、掩体、刷怪点、可破坏物、车站**。

**(B) 动态分桶 `Agents.prototype.bucket(C)`（`agents.js:671-695`）— 结构对，实现不行**

```js
const out = new Map();
for (const c of this.cars) {
  this.carWorld(c, road, tmp);
  const k = Math.floor(tmp.x/C) + ':' + Math.floor(tmp.y/C);      // ← 字符串键！
  let l = out.get(k); if (!l) { l = []; out.set(k, l); } l.push(c);
}
```

调用点只有一处：`render.js:1848` `const buckets = agents && agentAlpha > 0 ? agents.bucket(C) : null;`，随后每 chunk `buckets.get(ci+':'+cj)` 取列表。

**三个致命点（新游戏必须改）**：① **每帧新建 `Map` + 每桶一个 `Array`**——1000 只丧尸即每帧几百次分配，GC 每 2–3 秒抖一次，帧时曲线是锯齿；② **字符串键 `"12:7"`** 每帧拼几千个，直接进 old space；③ **每实体都重算世界坐标**（`carWorld` → `U.posAt` 二分查找），即使不在视野内。

**改造（保结构换实现）**：

```js
class EntityGrid {
  constructor(tile, W, H) {
    this.tile = tile; this.TW = Math.ceil(W/tile); this.TH = Math.ceil(H/tile);
    this.b = new Array(this.TW * this.TH);
    for (let i = 0; i < this.b.length; i++) this.b[i] = [];   // 只 new 一次
  }
  clear() { for (const c of this.b) c.length = 0; }           // O(桶数)，零分配
  insert(e) {
    const k = ((e.y/this.tile)|0) * this.TW + ((e.x/this.tile)|0);   // 整数键
    this.b[k].push(e);
  }
  at(ci, cj) { return this.b[cj * this.TW + ci]; }
}
```

再叠加 **3 帧一建**（丧尸位置变化慢于感知阈值）+ **只插入视野内 + 一圈余量**。

### 7.3 三重裁剪（全部可抄）

最内层在 `drawList`（`agents.js:713`）：`const screen = R.P(a.wx, a.wy, 0, pa); if (screen.x < -12 || screen.y < -12 || screen.x > R.w + 12 || screen.y > R.h + 12) continue;`

三级依次是：① 世界 bbox 裁剪——路段/区段 `bbox` 与 `view` 求交（`agents.js:418`、`render.js:2040`）；② 分桶裁剪——只遍历视野内 chunk（`render.js:1857`）；③ 屏幕坐标裁剪——投影后 `−12…w+12` 跳过（`agents.js:713`）。第 ③ 级最便宜（一次 `P()` + 4 次比较），且能兜住投影后仍在视野外的实体。对丧尸：**先 cheap cull（世界 bbox），再 project，再 screen cull**。

### 7.4 最终处方

**抄**：`bucket + drawList` 骨架（按 chunk 聚合 → 与建筑交错 → 免费遮挡排序）；`adaptDetail` 三档；`drawList` 屏幕裁剪；`Geo.buckets/query` 静态索引；`isoChunkGen` 的 generator+yield 分帧；`maxPeds` 封顶 + tier 缩放。

**不要抄**：`bucket()` 每帧 `new Map` + 字符串键（换持久化扁平网格）；`cars` 的「代表性抽样」哲学（丧尸要 HP/碰撞/状态机）；`carIndex` 按 link+lane（`agents.js:530`，除非丧尸严格沿轨道走）；无固定步长主循环（`main.js:241`，物理/碰撞必须 `fixedStep=1/60`）。

**额外必须自建的三样（底座完全没有）**：① **丧尸软分离**——上百实体挤在一起会重叠成黑块，用网格邻居 O(n·k) 推力（查 3×3 桶）；② **弹丸/命中检测**——底座**没有任何碰撞检测**（`carIndex` 只是索引，不做相交），自建「线段 vs 圆」扫掠 + 网格加速；③ **渲染批次合并**——每只丧尸 `beginPath/fill` 两次即 300 只 = 600 次 draw call，必须按颜色/状态分组合并成几条路径（照抄 `drawGround:553` 的 `Path2D` 批量 + `render.js:691` 的 `path(arr)` 模式）。

## 10. 给主设计师的 5 条结论

**① 投影层是整个底座最干净、最可复用的部分——先抄完它再谈别的。**
`computeTransform` + `P` + `unproject`（`render.js:345-369`）是 25 行纯数学，把「2D 俯视 ↔ 2:1 等距 2.5D」做成一个 `cam.t` 在 0→1 连续插值的参数，全项目所有绘制只认 `tEase` 一个数，没有第二套分支。新游戏只需定三条：世界单位取 1 m（`CELL_M` 从 250 降到 8–20）、`ISO` 保留 2:1、`EX` 从 2.0 提到 3.0（垂直夸张 1.64×→2.46×），列车和废墟立刻「立」起来，而**代码一行不用改**。

**② 列车不要照抄「描边带」，但一定要照抄它的定位算法。**
`drawTrains`（`agents.js:245-372`）把车厢画成屏幕空间的一条粗线——经营游戏够用，对「丧尸爬车」不够，因为车厢没有真实侧立面。但定位算法是精品：`trainPos` 用运动学解析解算里程（纯函数，可暂停/读档/跳时间）、`trainSpan` 展开车身、`joints[]` 每节接缝独立在弧长曲线上取点（转弯自动分节、零旋转矩阵）、`off=0.055*dir` 做法线偏移。保留这四步，只把「`stroke` 一段线」换成 `prism()` 一个矩形棱柱，就同时拥有正确过弯和真实侧立面——约 80 行，却是「车厢改装」玩法能否成立的物理基础。

**③ 武器挂点用「世界坐标 + 高度」，不要用屏幕偏移。**
`P(x,y,h)` 自带 `−h·hs`，意味着你可以**在世界空间**算炮塔位置、目标与弹道（`atan2`、射程、扇形），再把两端各自过一次 `P()` 得屏幕坐标——透视缩短、缩放、2.5D 倾斜全部自动正确。唯一的规矩是：**逻辑全在世界空间，绘制才过 `P()`**。反例是现有车门/乘客（`agents.js:339-358`），它们在屏幕空间偏移，缩小时不变形但也不与世界绑定，只能做纯装饰。写死这条规矩，能避免新游戏 80% 的「子弹和准星对不上」类 bug。

**④ 特效的数据结构能直接吃，但容器必须重写。**
`{kind,x,y,o,t,dur,seed}` 七个字段够用：`trace` 几乎就是弹道、`burst` 就是爆炸、`dust` 就是血雾、`region` 就是飘字。但有四个硬伤：上限 160 且用 `shift()` 淘汰（一秒 200 发就丢光）、`t` 在 `drawFx` 里推进（暂停/掉帧时错乱）、从不设 `globalCompositeOperation='lighter'`（爆炸没有光）、全部画在最后（血泊压不住车）。重写约 200 行。**顺手一定要做一件事**：把「永久留痕」（弹孔、血泊、履带印）烘焙进地面 chunk 缓存（`renderGroundChunk`，`render.js:822`），而不是逐帧画——这是 chunk 架构白送的礼物，让战场「越打越脏」且零额外开销。

**⑤ 镜头「跟随列车 + 战斗拉远」，`follow.js` 只完成一半，补三处就够。**
`Follow.tick`（`follow.js:139-142`）只有 4 行位置插值（`k=1−exp(−dt·7)`），接管协议干净（每帧置空 `cam.fly`/`cam.anchor`，不与 `updateCamera` 打架），但缺三样：**没有前视**（高速时列车贴屏幕后缘，补 `o.x+cos(a)·v·0.55`）、**没有死区**（小抖动带动全屏，补 46 px 判定）、**没有战斗反馈**（补 `c.tz = base·(1−0.28·smooth(combat))`，只改目标值，让 `updateCamera` 的对数指数逼近 λ=14 白送缓动）。再把 `cam.ox/oy` 在 `computeTransform` 末尾加一个衰减的 `shake` 偏移，就得到全局屏幕震动——因为**所有**绘制都经过这两个量，连缓存的 chunk 贴图都会一起抖，成本为零。
