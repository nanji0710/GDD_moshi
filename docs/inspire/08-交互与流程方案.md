# 08 · 交互与流程方案：玩家到底在操作什么

> **一句话结论**：现在这版是「**看**」的游戏，不是「**玩**」的游戏——玩家每分钟真正必须做的操作不到 1 次。补法不是加操作，而是加**干预点**：3 个技能（已有）+ 每节车厢一条目标优先级 + 一次「点名集火」点击，把密度拉到 10–12 次/分钟；同时把站内那 18 秒从「倒计时抢购」改成「真暂停的改装台」。

- 基准：`E:\github\sss\prototype`（含 14:42 加入的 `js/v2.js` 技能卡与撬轨者），代码行号以当前工作副本为准
- 证据来源：① 截图 `tools/shots/02-play.png`、`05-combat.png`；② headless 实跑 30 秒采样（下表的数字都是跑出来的）；③ 逐行核对 `ui.js / train.js / main.js / zombies.js / v2.js / cfg.js`

## 0. 先看实测：这 30 秒里玩家做了什么

以 8 门武器、弹药 6000、速度 1× 跑一段（`node` + headless Edge，采样 2.5s 一次）：

| 时刻(s) | 状态 | 速度 m/s | 前方 | 弹药 | 废料 | 击杀 | 车体 |
|---|---|---|---|---|---|---|---|
| 3 | 停靠 | 0 | 0 | 5972 | 445 | 15 | 1000/1000/1000/1000 |
| 24 | 停靠结束（24s！） | 0 | 0 | 5741 | 736 | 112 | 满 |
| 25.8 | 出站 | 3 | 2 | 5741 | 736 | 112 | 满 |
| 31.8 | 区间 | **11.4**（满速 34） | 12 | 5668 | 820 | 140 | 满 |

四件事直接决定了本方案的取向：

1. **玩家 0 次操作**：这 30 秒里没有任何一次操作是"必须做"的。可用的输入只有 `暂停/1×2×3×`（`ui.js:42-48`）、拖镜头（`main.js:303-308`，拖了就停止跟随）、滚轮缩放（`main.js:329-337`）、点车厢开改装（`main.js:316-328`，会暂停 `ui.js:200-201`）。
2. **列车被"看不见的手"踩了刹车**：满速 34 m/s，实测只有 11.4。原因是 `blockMul = 1 - 前方数量×0.055`（`train.js:95-104`）——前方 12 只就把速度压到 34%。HUD 只显示"前方 12"（`ui.js:122-124`），**没有一个字解释车为什么慢**。
3. **数值在骗人**：改装面板写"实测 DPS 1043"（8 门合计，`ui.js:207`），但 `dps()` 被当成**单发伤害**在用（`train.js:213,223` + `w.a.cd = 1/rof`），实际输出 **11176**，差 **10.7 倍**。玩家按面板做决策，一定会错。
4. **压力不在弹药，在废料**：实测平均耗弹 ≈11/s（理论满火力 148/s，`train.js:191`），6000 发能撑十分钟；但开场只有 260 废料（`cfg.js:85`），8 个挂点光机枪就要 720 废料 → **前两站玩家是"装不起枪"，不是"打不过"**。

## 1. 战斗中玩家的手在干什么

### 1.1 三方案对比

| 维度 | **A 全自动**（现状+技能） | **B 半自动·干预式**（推荐） | **C 手动瞄准射击** |
|---|---|---|---|
| 玩家每分钟操作 | **0–2**（实测 30s 内 0 次必须操作）；技能按满理论 **4.6**（CD 25/40/45 + 持续 3/5/6，`v2.js:15-17,32`），实战约 3 | **10–12**（下面有算账） | 60–120 |
| 操作是什么 | 按 Q/W/E、点 1/2/3 | 技能 + 切目标优先级 + 点名集火 | 鼠标/手指持续瞄准、扣扳机 |
| 爽点来源 | 看数字涨、看爆炸 | **"我提前按了刹车/我把火力挪到了裂开的那节车"** | 枪法、压枪、走位 |
| 失败归因 | ✗ 模糊：8 门全自动，输了只能怪"枪不够" | ✓ 清晰：撬轨者没点掉 / 优先级设错 / 技能空转 | ✓ 清晰但**归因到手上**，不是归因到改装 |
| 实现成本 | 已完成（`v2.js`） | **+1.5 天**（A2 优先级 S、点名集火 S） | +2 周（瞄准、弹道、掩体、命中判定，收益与"车厢改装"主线冲突） |
| 手机端 | ✓ 最好（3 个大按钮） | ✓ 好（点选 44px 目标，2 指法即可） | ✗ 差（边跑边瞄 + 8 炮塔抢视线，拇指遮画面） |
| 与"改装"主线的耦合 | 弱（战斗与改装互不影响） | **强**（装在哪节车、装什么，直接决定干预点够不够用） | 弱（手比枪重要，改装退化成数值） |

### 1.2 明确推荐：**B，但定义要收紧**

推荐 B 的理由（全部来自这个场景本身）：

1. **车在跑、丧尸四面八方来**——玩家不可能同时盯 4 个方向，C 的"瞄准"在 2.5D 俯视 + 移动镜头下会变成"追着点小点"，这是最差的触屏体验。
2. **8 个炮塔自动开火是这款游戏的卖点，不是缺陷**。玩家买的是"我造了一台机器"，不是"我操作一台机器"。C 会把这个卖点稀释成"你有 8 个很吵的背景装饰"。
3. **A 已经证明了不行**：30 秒里 0 次必须操作，等于没有玩家。而且 A 的问题不是"太简单"，是**输了不知道为什么**（实测 8 门武器 30 秒车体零损伤，玩家只会觉得"这游戏没难度"，直到某一局突然崩盘）。
4. **B 的每一次操作都能追溯到"改装决策"**：你把近防装在 1 号车还是 4 号车，决定了点名集火时火力覆盖快不快——这让 §2 的改装界面有了存在意义。

**B ≠ 更多按钮。** B 的准确定义是：**玩家只做"干预"，不做"操作"**。任何需要瞄准、需要连点、需要精确时机（±0.2s）的动作，都不属于 B。

### 1.3 B 的三个动词（这就够了）

| 动词 | 输入 | 频率（每波） | 上限 | 实现量 | 挂哪 |
|---|---|---|---|---|---|
| ① 技能卡 | `Q` 紧急制动 / `W` 全弹齐射 / `E` 强制过载 | 1–2 次 | 3 个，CD 25/40/45s | 已完成 `v2.js:14-49` | 补：CD 三段表现（见 §1.4） |
| ② 车厢优先级 | 点车厢卡 → 三选一：`最近` / `最危险` / `最远` | 1 次 | 每节车 1 个 | **S（半天）** | `pickTarget()` 加权重（`train.js:273-281`），`cars[k].priority` |
| ③ 点名集火 | 点一只丧尸 → 全车 5s 内优先它（有 8s CD） | 2–3 次 | 全局 1 个目标 | **S（1 天）** | `game.focusZb` + `pickTarget` 加权 + 点选命中（抄 `pickCar`，`main.js:384-395`） |

**操作量算账**（实测：一波间隔 ≈26s×(0.8~1.3)，`cfg.js:81` + `zombies.js:63` → 约 2.3 波/分钟）：

```
每波：技能 1.0 + 优先级 1.0 + 点名 2.5（精英 4.5%、大群 12%、撬轨 8.5% 都会触发）
     = 4.5 次 × 2.3 波/分钟 ≈ 10.4 次/分钟
再加站内改装（每 80s 一站，3–6 次点击）≈ +2.6 次/分钟
合计 ≈ 13 次/分钟  →  正好落在「半自动 10–20」的有效区间
```

**为什么不是再加第四个动词**：三个动词已经对应三种不同的决策（时机 / 布局 / 应急），第四个只会稀释。真要加，加在**站内**（改装、补给、路线），不是战斗里。

### 1.4 每个动词的交互细则

**① 技能卡**（现状 `v2.js:254-299`，CSS `style.css:282-331`）

- 位置：现在挂在顶栏最右（`v2.js:256,274`）——**手机端够不到**，见 §6。
- CD 表现要三段：`可按下`（描边亮 + 呼吸）/ `冷却中`（图标灰 + 自下而上的填充条，`v2.js:282` 现在只有填充）/ `生效中`（整块点亮 + 剩余秒数）。现在只有 2 段，玩家分不清"冷却"和"没冷却但没用"。
- 触发反馈必须有：技能本身要有 0.2s 的屏幕效果（今有 `Fx.shock`，`v2.js:38`），否则玩家会觉得"我按了但没发生"。

**② 优先级**（要新做，最便宜的一件）

```
点车厢卡 → 卡片原地展开 3 个小按钮（不弹抽屉！）
  [⊙最近] [⚠最危险] [➤最远]
最危险 = 正在啃车的 +30%、撬轨者 +50%、朝列车加速的 +20%
```
- 关键：**不能弹抽屉**。一旦弹抽屉就暂停（`ui.js:200-201`），战斗中弹暂停=节奏断裂。做成卡片内的 inline 三选一。
- 视觉：卡片右上角一个常驻小图标（⊙/⚠/➤），一眼看出这节车在打谁。

**③ 点名集火**

- 手势：在画布上点中一只丧尸（命中半径 28px，参考 `pickCar` 的 46px 略收紧）→ 该丧尸头顶出现红色准星 + "集火"标签，8s 内所有炮塔优先它。
- 为什么这个不违反"不做瞄准"：它**不要求精准**（点错代价极小，只是浪费 8s CD），而且**它把"最危险的那只撬轨者"变成可点掉的目标**——正好补上 C2 撬轨者（`v2.js:120-152`）目前"只能看着它撬轨"的空洞。
- 反向用途：撬轨者、爬车者、喷酸者出现时，玩家点名 → 全车火力瞬间转过去 → 这就是 B 方案的"爽点峰值"。

### 1.5 明确**不做**的三件事

| 不做 | 原因 |
|---|---|
| 手动瞄准/扣扳机（C） | 与 8 炮塔自动开火冲突；2.5D 视角点选小目标体验差；手机端拇指挡画面 |
| 拖放武器到挂点 | 全仓库 `dataTransfer/draggable` 出现 0 次（见 `docs/borrow/03-界面外壳.md`），拖放要新写指针捕获 + 拖影 + 命中回弹，成本是"点两次"的 5 倍 |
| 战斗中实时改装（不暂停） | 改装需要阅读数字，实时改装必然被丧尸打断；且会让"站内改装"这个节奏点消失 |

## 2. 车厢改装界面的三种形态

### 2.1 现状：点击流，但有三个卡点

流程：底部车厢卡 → `.slot`（`ui.js:76-81`）→ `openSlot()` 抽屉（`ui.js:188-257`）→ 武器列表（`ui.js:231-251`）→ 安装/升级/拆下。

三个卡点（都在代码里，可直接验证）：

1. **一次只能看一个挂点**。8 个挂点 = 8 次"点开 → 读 3 行数字 → 点关闭"，每次都会把前面的比较忘掉。而改装的核心乐趣就是**比较**。
2. **站内只有 18 秒，而且在倒计时里**：`onArrive` 打开站内面板（`main.js:153-160`）但**不暂停**，`dockT` 照样走（`train.js:83`），18s 一到 `leaveStation()`（`train.js:152-159`）→ `main.js:144` 把抽屉强制关掉。**你还没比较完，车已经开走了。**
3. **关掉站内面板就回不去了**：`openStation` 只在 `game.begin`（`main.js:111`）和 `onArrive`（`main.js:159`）调用，关闭后没有任何入口能重开——除非再坐一站。这是 bug 级。

> 顺带：`openSlot` 里 `g.speed = 0`（`ui.js:200-201`）+ 关闭时恢复（`ui.js:254-256`）——所以**唯一能在站内安心看武器的办法是先点一个挂点（触发暂停），这是一个玩家永远不会知道的隐藏机制**。

### 2.2 三形态对比

| 维度 | ① 点击流（现状） | ② 车厢全景（横向剖面） | ③ 网格拼装（Highfleet 式） |
|---|---|---|---|
| 长什么样 | 一列 8 行，点一行开抽屉 | 一条横向车厢带，4 节 × 2 挂点全部可见，点挂点就地弹武器卡 | 每节车一张格子图，武器占 1×2 / 2×2 格，有重量与电力 |
| 信息密度 | 低（一次一个） | **高（一眼 8 个 + 对比）** | 最高（空间 + 资源约束） |
| 开发量 | 0（已有） | **2–3 天**（纯前端，无新数据） | **2 周起**（新数据模型 + 冲突校验 + 拖放） |
| 上手成本 | 低 | 低（就是"更清楚的点选"） | **高**（要先教格子/重量/电力） |
| 策略深度 | 低（只有装什么） | 中（多了"装哪节车"） | 高（位置、配重、供弹、功率） |
| 手机适配 | 差（8 行列表 + 抽屉，竖向滚动） | **好**（横向滑动 + 大按钮） | 差（格子图在 375px 宽上无法操作） |
| 与现有代码冲突 | — | 无（可复用 `openSlot` 的武器卡逻辑） | 大（`slots` 数组要换成占位图） |
### 2.3 推荐演化路线（先做哪个、什么时候升级）

| 版本 | 做什么 | 工期 | 升级触发条件 | 数据结构改动 |
|---|---|---|---|---|
| **V1（本周）** | 把「点击流」修对：① 站内改真暂停（§4.2）；② 站内面板加"改装台"区块，8 个挂点**同屏列出**（不是 8 行文字，是 4 张车厢小卡横排）；③ 关掉抽屉可再开（顶栏加"改装"按钮） | **1 天** | 现在就做，不做会一直卡 | **零** |
| **V1.5（下周）** | 把 V1 的"8 挂点同屏"升级成**车厢全景**（②）：横向车厢带 + 点挂点就地弹武器卡 + 车厢之间画连接器；站内用，战斗中点车厢卡还是走轻量版 | **2–3 天** | 当玩家开始问"装 1 号车和 4 号车有区别吗" | **零**（只加 DOM 结构，`cars[k].slots[j]` 原样） |
| **V2（有重量/电力之后）** | 网格拼装（③）：武器有占地、重量、功率，车厢有配重上限 | **2 周** | 当 B2（重量配重）/B3（电力网络）进入设计（见 `00-细节设计灵感.md`） | **大**：`WEAPONS[key]` 加 `size/weight/power`，`car` 加 `weightMax/powerMax`，`slots` 换成 `grid` 占位 |
| 不进 V3 | 自由拖放、任意位置摆放 | — | — | 拖放在触屏上是净损失 |

**关键判断**：①② 之间**没有数据结构改动**，所以 V1→V1.5 是纯增量、可随时停。只有到了 ③ 才动 schema——**这就是"什么时候升级"的量化标准：不是玩家抱怨界面不好，而是武器多到"只有位置信息不够用"时。**

## 3. HUD 信息分层

### 3.1 三层原则（一句话：HUD 只回答"我现在要不要动"）

| 层 | 回答的问题 | 显示条件 | 消失条件 | 位置 |
|---|---|---|---|---|
| **L0 常驻** | 我现在处境如何 | 一直在 | 只在赢/输时消失 | 顶栏 + 车厢条 |
| **L1 情境** | **为什么会这样** | 事件发生时出现 | 事件结束后 2s 淡出 | 顶栏下方 chip / 车厢卡上 |

### 3.3 三个专项

#### (a) 为什么减速——做一个"速度原因解析器"

现在同时有 **4 个减速源**，只有 1 个有 HUD 解释：

| 减速源 | 代码 | 有没有告诉玩家 |
|---|---|---|
| 前方丧尸（人体路障） | `train.js:95-104`（`blockMul`） | ❌ 只显示"前方 N" |
| 进站制动曲线 | `train.js:100-104` | ❌ |
| 轨道被撬（限速） | `v2.js:85-90,192-197` | ✅ `railchip`（`v2.js:270-274`） |
| 紧急制动技能 | `v2.js:34,195` | ❌ |

**做法**：在 `stepSim` 里算出"目标速度被谁压住"，存一个字符串到 `game.speedWhy`，UI 只负责显示。加到 `v2.js` 的 `stepSim` 包装里（`v2.js:183-205`）最省事：

```js
// v2.js 的 stepSim 包装内，算完 cap 之后

if (Skills.on('brake')) reasons.push('紧急制动');
if (tc < CFG.TRAIN.maxSpeed * 0.99) reasons.push('轨道被撬 ' + Math.round(tc * 3.6) + 'km/h');
if (this.zsAhead > 3) reasons.push('前方尸群 −' + Math.round(Math.min(0.84, this.zsAhead * 0.055) * 100) + '%');   // 与 train.js:97 同公式
if (this.train.state === 'dock') reasons.push('停靠');
if (this.train.horn > 0) reasons.push('鸣笛');           // 若以后加

```

```js
// ui.js tick 里新增（ui.js:105-150 之间）

  this._why = g.speedWhy;
  R_.why.textContent = g.speedWhy ? '速度 ' + Math.round(train.v * 3.6) + ' km/h · ' + g.speedWhy : '';
```

**显示规则**：只在"当前速度 < 满速 85%"时出现；出现时用 `--warn` 色（`style.css:12`），并**在路线条上画一个减速段**（`route-fill` 变暗），让玩家一眼看到"这段是慢的"。

#### (b) 哪节车厢在挨打——三级反馈

现在只有：世界里的细血条（受损才出现，`main.js:274-283`）、车厢卡 hp 数字（`ui.js:128-134`）、车体闪白（`main.js:207-208`）。**玩家在 3× 速度下几乎不可能注意到是哪节车在掉血。**

| 级别 | 触发 | 表现 | 代码挂点 |
|---|---|---|---|
| 1 级：车厢卡 | 该车 hp 每掉 1% | 卡片**抖动 0.15s + 边框闪红**；同时打印 `-7` 小字 | `ui.js:128-148`，新增 `car.hitT`（`zombies.js:111-114` 里累加） |
| 2 级：世界内 | 正在被啃 ≥3 只 | 车厢**边缘锯齿闪光**（像被扒） | `main.js:232-243` 的窗带已有 `flash`，扩展成"受损等级→颜色" |
| 3 级：镜头外 | 攻击者在视野外 | 屏幕边缘**红色三角**指向最近攻击者 | `main.js:481-506` 的 `drawBanners` 里加 |

**关键设计**：把"车体 100%"（`ui.js:38`）改成 **4 段微条**（`▮▮▮▮`，最弱那节闪），因为玩家真正关心的是"哪节先炸"，不是一个平均百分比。

#### (c) 弹药/燃料提前预警——从"0 才提示"变成"还剩几秒"

现在：弹药**完全没有预警**（`ui.js:115` 没有任何 class 逻辑），到 0 才 toast 一次（`main.js:146-147`）；燃料只有 `<45%/<20%` 变色（`ui.js:117`）和耗尽后的横幅（`main.js:482-490`）。

**做法：用 EMA 估算"还能撑几秒/几公里"，而不是看百分比。**

```js
// ui.js tick 内，每帧喂，1s 出一次结论
this._ammoRate = U.lerp(this._ammoRate || 0, (this._lastAmmo - g.ammo) / Math.max(dt, 1e-3), 0.15);
this._lastAmmo = g.ammo;
const secLeft = this._ammoRate > 2 ? g.ammo / this._ammoRate : Infinity;   // 打空剩余秒数
R_.ammo.textContent = U.fmt(g.ammo) + (secLeft < 90 ? ' · ' + Math.round(secLeft) + 's' : '');
R_.ammo.className = secLeft < 20 ? 'bad' : (secLeft < 60 ? 'warn' : '');
```

燃料同理，但换成**距离**而不是时间（因为燃料只和里程相关，`train.js:112`）：

```js
const kmLeft = g.fuel / CFG.ECON.fuelPerKm;                          // 还能跑多少 km（fuelPerKm=7.2，cfg.js:88）
const nxt = world.stations[train.nextIdx + (train.state === 'dock' ? 1 : 0)] || null;   // 同 ui.js:112 的取法
const toNext = nxt ? (nxt.s - train.s) / 1000 : 0;
R_.fuel.textContent = Math.round(g.fuel) + '%' + (kmLeft < toNext * 1.6 ? ' · 差 ' + (toNext - kmLeft).toFixed(1) + 'km' : '');
R_.fuel.className = kmLeft < toNext ? 'bad' : (kmLeft < toNext * 1.4 ? 'warn' : '');
```

**阈值表**（直接照抄）：

| 资源 | 正常 | 预警（黄） | 危险（红） | 触发动作 |
|---|---|---|---|---|
| 弹药 | >90s | 60s | 20s | 20s 时顶部 chip "弹药将尽 · 建议关掉喷火" |
| 燃料 | >1.6×到下一站 | 1.4× | <到下一站 | 红色时建议"减速可省油？"（现阶段燃料不随速度变，先只提示） |
| 车体 | 最弱车 >65% | 35–65% | <35% | 红色时车厢卡直接脉冲（§3.3b 1 级） |

**注意一个真实陷阱**：`燃料` 目前跟战斗无关（喷火器扣的是弹药，`train.js:191`，虽然 `cfg.js:41` 写"吃燃料"），所以燃料百公里几乎恒定，玩家不会在意。**要么让喷火真的烧燃料，要么把燃料从顶栏降级**——现在这样是"占着一个 L0 位置但没有决策价值"。

## 4. 时间控制与节奏

### 4.1 现状的三个问题

| 问题 | 证据 | 后果 |
|---|---|---|
| **进站不暂停** | `onArrive` 只 `openStation`（`main.js:153-160`），速度不变 | 你在读武器价格时，丧尸在咬车（规则文本自己都写了"它们在站里也会咬你"，`ui.js:344`） |
| **18 秒强制出站** | `dockT = dockSec`（`train.js:121`，`cfg.js:27`）+ `leaveStation`（`train.js:152-159`） | 还没比完价就被踢走；`main.js:144` 还会把抽屉关掉 |
| **关掉面板回不去** | `openStation` 只有两个调用点（`main.js:111,159`） | 误点"关闭" = 这一站白停 |

补充实测：开场停靠 **24 秒**（`dockSec 18 + 6`，`main.js:92`）；在"已挂 8 门炮"的测试条件下，这 24 秒里自动打出约 **100 击杀、废料 +291**（445→736）——说明停靠期间武器照常开火、丧尸照常贴上来（`train.js:89`），**"站内"其实是战斗时段，玩家却在看菜单。这是全游戏最割裂的 24 秒。**

### 4.2 推荐时间轴

| 阶段 | 时间 | 玩家状态 | 设计 |
|---|---|---|---|
| 站内 | **不限时**（软上限 45s） | 真暂停（`speed=0`） | 到站自动暂停 + 面板；"出发"按钮；45s 后开始 10s 倒计时提示"自动发车"，可关 |
| 出站加速 | 3–5s | 观察 | 加速曲线已有（`train.js:105-106`） |
| 区间 | 15–25s | **动手** | 波次预告（L1 chip）→ 点名/优先级/技能 |
| 尸群接触 | 8–20s | 高峰 | 首次接触时**自动降速到 0.6×**，持续到威胁解除（可关） |
| 到站前 80m | 3s | 收尾 | 制动提示（"减速进站"），清残余 |

**关键三条**：

1. **站内必须真暂停**。这是把"倒计时抢购"变成"改装台"的前提，也是 §2 那条演化路线能落地的前提。
2. **不要做"进站自动弹窗抢焦点"**：现在 `onArrive` 直接 `openStation`，等于强制打断。改成"停稳后 0.5s 弹出"，且**允许 Esc 关闭后从顶栏重新打开**。
3. **战斗速度与威胁挂钩**：`1× / 2× / 3×` 保留，但**接触瞬间自动降到 1×**（避免 3× 里死得莫名其妙），威胁解除 3s 后恢复玩家原选择。这条直接解决"3 秒没看就崩"。

### 4.3 「目光离开 3 秒」能错过什么（量化）

| 关联量 | 数值 | 来源 |
|---|---|---|
| 3 秒行驶距离（满速 34 m/s） | **102 m** | `cfg.js:20` |
| 3 秒行驶距离（被压速 11 m/s） | 33 m | 实测 |
| 波次预警提前量（大群生成在 +150~300m） | **4.4–8.8s**（满速）/ 13–27s（压速） | `zombies.js:163` |
| 一节车厢被 20 只围住能撑多久 | **≈8s**（20×6.4 dps → 1000hp） | `cfg.js:73` + `zombies.js:109-111` |
| 一节车厢被 5 只围住 | ≈31s | 同上 |

结论：**3 秒在"满速 + 大群 + 已被贴身"时会损失 ~37% 的一节车厢**，但在"压速 + 预警期"里几乎无影响。所以容错不该靠"慢"，该靠**三件事**：

1. **把预警从 toast 升级成 L1 chip + 倒计时**（现在是 2.6s 的 toast，`ui.js:179-185`）；
2. **首次接触自动降速**（§4.2 第 3 条）；
3. **关键时刻给"事后可读"的记录**：顶部 chip 一直显示最近 5s 的受击总量（"车厢2 -35"），玩家回神能立刻知道发生了什么。


**不劝退的 4 条规则**：
1. 死因必须**可归因到玩家的一次决策**（不是"丧尸太多"）。
2. 失败画面**不要黑屏**：保留战场，用 30% 暗度压住（现在 `style.css:258-263` 已经这么做，✓）；第一次死亡给**教学式建议**，第三次以后不再教。
3. **重开耗时 < 1.5s**（现在 `location.reload()` 要重跑整个世界生成，约 2s 级，且会丢掉本局所有数据）。

## 6. 手机端

### 6.1 结论：横屏，单手点选，不追求单手全操作

理由：路线条（`style.css:59-76`）、4 张车厢卡（`style.css:113-127`，每张 168px）、技能栏（`v2.js:254-274`）都是横向排布；竖屏（375px）连 3 张车厢卡都放不下。**另一个更硬的事实：原型现在只有鼠标事件**（`main.js:303-352` 全是 `mousedown/mousemove/mouseup/wheel/keydown`），`pointerdown` / `touchstart` / `setPointerCapture` 出现 **0 次**——手机端第一件事是把输入层换成 Pointer Events，而不是调样式。

| 竖屏降级 | 车厢条改成**竖向 4 行**贴右边缘（只留 hp + 2 个小挂点）；顶栏只留 废料/弹药/车体 + 暂停，其余进"更多"；技能栏移到底部中央（拇指区）；场景上下留黑边等比缩放，不做动态旋转 |

## 8. 如果只能做 3 个交互决策

**① 战斗中只允许三个动词：技能（Q/W/E 已有）+ 每节车厢一个优先级 + 一次点名集火。**
不做手动瞄准、不做拖放、不做实时改装。理由是这款游戏卖的是"我造了一台机器"，不是"我操作一台机器"；三个动词把操作密度从实测 0–2 次/分钟拉到 ~13 次/分钟，且每次操作都能追溯到改装决策。**验收：一局 12 分钟，玩家至少按 60 次有意义的键/点击，且能说出每次为什么按。**

**② 站内是真暂停、可重开、准备好了再发车；战斗中首次接触自动降到 1×。**
把现在那 24 秒"边被咬边看菜单"（`main.js:92` + `train.js:89`）改成真正的改装台，是 §2 所有界面升级的前提。同时把"为什么突然崩了"消灭在源头：接触瞬间降速 + 常驻预警 chip（`zombies.js:66` 的 toast 升级成 L1）。**验收：玩家读完整的武器对比不会被踢出站；3 秒不看屏幕最多损失 1/3 节车厢，且回神能立刻知道发生了什么。**

**③ HUD 只加三个"为什么"，其余全部下沉：速度为什么慢（速度原因 chip）、哪节车在挨打（车厢卡抖动 + 镜头外箭头）、还能撑多久（弹药秒数 / 燃料公里数）。**
现在 HUD 的问题不是信息少，是**信息不解释**：车被看不见的手压到 34% 速度（`train.js:96-97`）、面板 DPS 差 10.7 倍（`ui.js:207` vs `train.js:213`）、弹药 0 才提示（`main.js:146-147`）。把这三个"为什么"补上，比再加十个数字有用。**验收：随便截图一帧，新玩家能说出"车为什么慢、我该动哪里"。**
