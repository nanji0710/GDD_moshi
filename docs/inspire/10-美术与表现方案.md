### 1.2 明确推荐：**C 为骨、A 为皮（不选 B）**

1. **这是读图任务不是看风景任务**：玩家 90% 注意力在列车周围 200 m 那 40% 屏幕，信息密度极高，高对比是唯一不糊的路。
2. **数量本身就是压迫感，但数量必须先被看见**。140 只读不出来，玩家的感受是「卡顿」而不是「恐怖」。
3. **A 的优点可以白拿**：C 的地面 L=15% 已达到 A 的夜地水平，只是中景和演员不再跟着暗。
4. **B 不适合**：硬描边会把丧尸压成抽象符号，且无法做夜晚。
5. C 的廉价风险用两条规则压住：**背景低彩度** + **特效必须 `lighter`**。

### 1.3 合成规则（可直接当验收标准）

```
明度三档分离 + 彩度独占
100% ┤ · · · · · · · · · · · · · · · ·  白热特效（lighter）
 85% ┤ ████████████  演员：丧尸 75–82%    ← 唯一高彩度区（≥110）
 60% ┤ ████████  玩家：列车/炮塔 55–70%   ← 冷钢 + 少量琥珀
```

- **规则 1**：背景与中景彩度 ≤30；只有丧尸/精英/血/特效允许 >100。
- **规则 2**：**40–55% 是禁忌明度带**——旧版所有东西都在这一带。新元素先问落哪一档。
- **规则 3**：高光固定**左上 -45°**，投影固定**右下**，长度 = 高度 × 0.22。

### 3.1 高度系数：本方案最大的单项杠杆

上一轮评估的「1.64× 垂直夸张」在原型里只剩 **0.655**。但**不要改 `tilt`**——改 tilt 会同时压扁地面 y（`cos` 变小），整张地图被拉长变形。正确做法是**把高度从 tilt 里解耦**：

```js
// cfg.js CAM:  hScale: 1.6
// main.js:47  P() 唯一一行
out.y = this.oy + y * this.cosT * this.z - (h || 0) * this.sinT * this.z * CFG.CAM.hScale;
//                                              ↑ 只在这里乘 hScale；flat() 不含高度，不受影响
```

比例从 `0.655` → `1.05`（hScale 1.0 / **1.6 建议** / 2.4 / 3.0 分别对应 0.655 / **1.05** / 1.57 / 1.96；2.4 起低层会歪，3.0 过头）。代价：一个乘法；上限卡在 1.8 以免 h<3 的低楼「拉丝」。

## 4. 破坏与脏化：「越打越脏」且不回放不重算

### 4.1 三层结构

```
第 0 层 terrainChunk  烘焙一次，永不重画   地面色块/废墟/树/路/水
第 1 层 decalChunk    只追加，永不重算     血迹/弹坑/焦痕/碎屑
第 2 层 动态           每帧重画            列车/丧尸/炮塔/特效

 每帧：  drawImage(decalTile) × 可见块    ← 永不回放
 stamp：  ctx.fill() 一次，画 3–5 个椭圆 → 写进位图后即销毁
```

**「不回放、不重算」靠三条保证：**
1. **只画一次进位图** → 之后每帧是 `drawImage`，与「历史上画过多少次血溅」完全解耦。
2. **伪随机用 `hash(坐标, 序号)` 而非 `Math.random()`** → 同一格重进时结果一致，不需要存随机状态。
3. **损伤用确定性函数 `stage(hp)` + hash 选位置** → 不需要记录「第几次受损」。

### 4.2 数据结构（新增 `prototype/js/decals.js`，约 90 行）

```js
Z.Decals = {
  TILE_M: 256, PPM: 2, cap: 48,                     // 512×512/格；48 格 ≈ 50 MB
  tiles: new Map(),                                 // "ci:cj" -> {cv, ctx, used}
  ensure: function (ci, cj) {
    const k = ci + ':' + cj; let t = this.tiles.get(k);
    if (!t) {
      const cv = document.createElement('canvas'); cv.width = cv.height = this.TILE_M * this.PPM;
      t = { cv: cv, ctx: cv.getContext('2d'), used: 0 }; this.tiles.set(k, t);
      if (this.tiles.size > this.cap) this.evict();
    }
    return t;
  },
  stamp: function (kind, x, y, ang, r, seed) {      // kind: blood|crater|scorch|debris
    const ci = Math.floor(x / this.TILE_M), cj = Math.floor(y / this.TILE_M);
    const t = this.ensure(ci, cj), g = t.ctx, P = this.PPM;
    g.save(); g.setTransform(P, 0, 0, P, -ci * this.TILE_M * P, -cj * this.TILE_M * P);  // ← 世界坐标直画
    /* 按 kind 画 3–5 个椭圆 / 1 圆 + 4 条射线 */
    g.restore(); t.used = R.frame;
  }
};
```
> `setTransform(P,0,0,P,−ci·TILE·P,−cj·TILE·P)` 就是上一轮从 `city-and-metro/js/render.js:822-828` 学到的「**世界坐标直画 + transform 缩放**」——绘制函数完全不知道自己在画 chunk。

### 4.3 各脏化项

| 项 | 何时 | 怎么画 | 持久 |
|---|---|---|---|
| **血迹** | 丧尸死亡置位那一刻 | 3–5 个不规则椭圆（半径 hash 6–14 m）+ 1 条沿死亡方向拖尾（宽 2–4 m、长 15–30 m、alpha .5） | 永久 |
| **弹坑** | 迫击炮落点 | 深色圆 `#0a0e13` alpha .65 + 左上 1/4 亮弧 `#3d4a59` + 4 条散射碎屑线 | 永久 |
| **焦痕 / 碎屑** | 喷火爆炸 / 车厢摧毁 | 3 层同心椭圆 alpha .12/.18/.10 / 12 条短线段沿车体朝向 ±60° 扇形，`#2a3340` | 永久 |
| **轨枕被撬** | **不 stamp** | `drawTrack` 里用 hash 跳过：`if (R.hashCell(Math.floor(s/2.6),7,3) < 0.06) continue;` | 零存储 |
| **车体受损** | **不 stamp**（车在动） | 见 §4.4 | 确定性 |

### 4.4 车体受损：确定性 4 档（`main.js` `drawCar`）

```js
for (let i = 0; i < stage * 2; i++) { /* 用 R.hashCell(k*17+i,3,5)/(k*17+i,4,9) 在车顶/侧壁画 2–5 px 深色斑 */ }
```

### 4.5 LRU 与「训练方向」

```js
evict: function () {
  const arr = [...this.tiles.entries()].sort((a, b) => a[1].used - b[1].used);
  while (this.tiles.size > this.cap) {
    const [k, t] = arr.shift(); if (t.used >= R.frame) continue;
    this.tiles.delete(k); t.cv.width = t.cv.height = 1;      // 立刻释放显存
  }
}
```
列车**单向推进**，身后的贴花再也看不到 → LRU 自然只保留「前方 + 当前」。`cap=48` 覆盖约 3.1 km，足够。

## 5. 昼夜与天气：把「氛围」和「玩法」分开

### 5.1 三层定义 + 唯一接口

| 层 | 定义 | 改动范围 |
|---|---|---|
| **氛围层** | 只改像素，不改任何数值 | 雾/雨丝/闪电/暗角/色温/灯光 |
| **可读层** | 改「看见什么」，不改「打得怎样」 | 丧尸淡出距离、车灯照亮圈 |
| **玩法层** | 改数值，玩家必须应对 | 命中、射程、燃料、仇恨、刹车 |

```js
// cfg.js —— 一个对象，两处消费，不会出现「画了雨但没算雨」
Z.Env = { night: 0, rain: 0, fog: 0, lightning: 0 };   // 全 0..1
```

### 5.2 具体参数

| 环境 | 氛围（视觉） | 可读（看见） | 玩法（数值） |
|---|---|---|---|
| **夜** | 地面明度 ×0.62；色温 +12% 蓝；全屏 `#0a1630` alpha .18 | 车灯锥形照亮 90 m（径向渐变 + `lighter`） | 丧尸仇恨半径 ×1.3 |
| **雨** | 3 层视差雨丝（斜 12°，900/1400/2000 px/s）；屏幕雾 `#1e262e` alpha .28 | 丧尸 190 m 外 alpha→0（渐隐 40 m） | 直射武器射程 ×0.82、散布 ×1.55；喷火燃料 ×1.2；**迫击炮不受影响**；刹车距离 ×1.12 |
| **雾** | 屏幕雾 alpha .42 + 色温偏冷 | 丧尸 140 m 外淡出 | 所有射程 ×0.88；**车灯从「可选」变「必需」** |
| **闪电** | 全屏 +35% 白，80 ms，3–6 s 随机 | 闪光瞬间全场可见 | 闪光当帧暴露所有丧尸位置（含雾中） |

### 5.3 让玩家真的在意：**车灯 = 能见度 vs 仇恨**

```
              开灯                     关灯
能见距离    165 m → 260 m           165 m
开火窗口    提前 3.1 s（34 m/s）     贴身才看见
仇恨半径    ×2.2  ← 代价            ×0.75  ← 收益
适合        火力足、想快推            弹药紧、想苟过雨夜
```
实现只需一个布尔 + 两个乘数：渲染画锥形光（`lighter` 径向渐变），玩法 `aggroR = BASE * (Env.lightOn ? 2.2 : 0.75) * Env.nightMul`。**这一个开关把「雨夜滤镜」变成了战术决策。**

### 5.4 雨丝：180 条 = 1 个 draw call

```js
for (const r of rainDrops) {                       // 预生成参数，不每帧随机
  const sx = (r.x + t * r.sx) % (R.w + 200) - 100;
  const sy = (r.y + t * r.speed) % (R.h + 120) - 60;
  ctx.moveTo(sx, sy); ctx.lineTo(sx - 3, sy - r.len);   // 同一 beginPath 内
}
ctx.strokeStyle = 'rgba(180,210,240,0.22)'; ctx.lineWidth = 1; ctx.stroke();
```

## 7. 性能预算

### 7.1 实测基线（读代码推算，140 只 / zoom 2.4 / 1570×805）

**口径：一次 `ctx.fill()` 或 `ctx.stroke()` = 1 个 draw call。同一 `beginPath()` 里 200 个 `arc` 仍算 1 个。**

| 层 | draw call | 依据 |
|---|---|---|
| 天空 | 1 | `main.js:402-407` |
| 地面（260 m 块 + 碎屑） | ~40 | `world.js:159-176`：20 `fillRect` + 可见约 20 `ellipse` |
| 树 + 废墟 | ~270 | `world.js:210-239`：可见约 60 棵 × 2 + 约 50 座 × 3 |
| 轨道 / 站台 / 公路 / 河 | ~22 | `world.js:180-386`（枕木是**一条** stroke 里 670 段） |
| 列车 4 节 | ~60 | `main.js:187-284`：每节约 15 |
| **丧尸 140** | **~840** | `zombies.js:176-232`：**每只 6 次**（影/身/头/臂/2眼） |
| 特效 | 20–60 | `fx.js:44-143` |
| **合计** | **≈1250–1400** | 与「140 只 60fps」的实测吻合 |

> **瓶颈是「每只丧尸 6 次 draw call」，不是像素填充。** 140 只的像素开销 < 0.05 MP，可忽略。

### 7.2 目标：200 只 + 8 炮塔 ≤ 900

| 手段 | 节省 | 改动 |
|---|---|---|
| **地形/废墟/树/路烘焙 chunk** | **−320**（330 → 12 次 drawImage） | `world.js` 加 `bake()`；`main.js:409-412` 换成 `drawTiles()` |
| **丧尸合批（按状态分 3 组路径）** | **−700**（840 → ~10） | `zombies.js` 新增 `drawBatch()` |
| 丧尸 LOD 三档 | 远景 −40% | §2.4 |
| 特效池化 + 渐变按半径分桶缓存 | −30 | `fx.js` |
| 贴花烘焙 | **+12** | 新增 `decals.js` |
| 暗角 + 颗粒（缓存一张 overlay） | +2 | — |

**合批后**：12 + 12 + 6 + 200×~1.2 + 60 + 64 + 220 ≈ **360 draw call → 可跑 300–400 只**。

### 7.3 丧尸合批（`zombies.js` 新增 `drawBatch`）

```js
const g1 = []; for (const zb of list) if (!zb.dead && R.z >= 0.8) g1.push(zb);
// 身体：一次 beginPath 里 200 个 ellipse → 一次 fill
ctx.fillStyle = P.zombie; ctx.beginPath();
for (const zb of g1) { R.P(zb.x, zb.y, 0, p); ctx.ellipse(p.x, p.y - r*0.95, r*0.52, r*0.86, 0, 0, 6.2832); }
ctx.fill();
// 描边：同一路径再一次 stroke；红眼：200 个 arc 一条路径一次 fill
```
- **代价**：失去丧尸之间的 y 排序。解决：**只放弃丧尸 vs 丧尸**（它们本就在一堆，重叠 1–2 px 无感），**保留丧尸 vs 列车/废墟**（分「车前」「车后」两批即可）。
- 用一点正确性换 3 倍性能，且视觉无感——**值得**。

### 7.4 像素填充预算（1080p = 2.07 MP）

每帧全屏填充层数上限 **4 层**（天空 / 地形 / 贴花 / 雾+暗角合并）→ 峰值 **8.3 MP/帧**，60 fps = 500 MP/s（Canvas2D 舒适区）。300 只丧尸的像素开销 < 0.12 MP，**完全不是瓶颈**；超过 5 层时把雾/暗角/颗粒预合成一张 overlay。

> **结论：预算按 draw call 定，不要按像素定。** 后者会误导你去优化丧尸尺寸，而真实开销是路径批次。

## 8. 一小时内能做完的 5 个视觉提升

> 按「改动行数 / 观感提升」排序，只改现有文件，不新增资源。总计 **≈45 分钟**（含调试），留 15 分钟缓冲。

### ① 全局高度系数 `hScale`（3 分钟，观感 +50%）★ 最高杠杆

### ② 压暗地面 + 换天空（6 分钟，+40%）

```js
// world.js:162  地面四色整体压暗（L 27–35% → 12–19%）
```

**做完这步丧尸会「自动」变亮**——对比是相对的，不需要动丧尸。

### ③ 废墟落地投影（8 分钟，+20%）

```js
// world.js:243  _quad 开头，画侧面之前插入
const so = h * 0.22;                                    // 影子长度 ∝ 高度
const sh = q.map(function (p) { return R.P(p.x + so * 0.6, p.y + so, 0, {}); });
```

### ④ 丧尸描边 + 红眼放大（10 分钟，+60%）

### ⑤ fx 开 `lighter`（8 分钟，+35%）

```js
// fx.js:50-138  switch 里，给发光类加合成模式（tracer/flash/boom/shock 各 case）

/* 原有绘制不动 */
```

闪光、爆炸、曳光立刻「发光」而不是「贴一张暗色圆」。**这是全项目唯一缺失的 Canvas2D 表现手段。**
